# Sealed SDK backend build inputs

A frozen complete SDK candidate installs and passes application check/test/build, but the canonical backend Dockerfile copies only manifests and backend/contracts sources. Its dependency install cannot find workspace-local file overrides under vendor. The CLI currently discards the underlying build output and reports only BACKEND_IMAGE_BUILD_FAILED; a diagnostic rebuild confirmed ENOENT for a verified SDK archive.

The backend template owns dependency build inputs. Add an optional readonly BuildKit context mount before dependency install and copy only the conventional vendor directory when present. Normal registry-only workspaces require no vendor directory. Existing .dockerignore remains authoritative and excludes credentials, local ops, caches and environment files. No mounts reach the runtime stage, and only the production deploy output enters the image. Preserve package hashes, lockfile overrides, source checks and compiler matching; no registry fallback or guard relaxation. Update the consuming application's Dockerfile from this same generic template. Test template boundary plus real image build using the complete frozen SDK and verify ordinary template checks. Rollback restores the previous template and SDK image candidate.
