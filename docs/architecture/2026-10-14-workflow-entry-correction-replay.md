# 首部插入与补正回放

现场证据：在首节点前插入审批改变startAt，却保留correction.next指向旧入口；严格校验返回WORKFLOW_CORRECTION_REPLAY_TARGET_INVALID。末尾插入不改变入口，不触发此问题。历史附件只用于离线复现，不重放其revision、operationId或人员数据。

所有权：contracts拥有结构编辑与补正语义，SDK画布调用同一编辑器；后端继续严格要求correction.next等于startAt。采用显式insert_start编辑，与普通插入分开，不持久化画布虚拟发起节点。首部人工/条件/业务/并行插入在一次不可变编辑中新增节点、改变入口，并仅重连原先指向旧入口的补正节点。多补正同处理；普通插入不改补正。首节点删除沿既有重连语义保持同一不变量。不得修复本来已经不合法的补正目标，避免默默吞掉坏草稿。

编辑保持旧节点ID、审批出口、绑定和应用代码归属；不改历史实例、运行版本、后端权限或校验。不引入存储、调用或并发状态。原草稿CAS/operationId、未知结果恢复及undo/redo继续包裹整个definition+binding，不分步保存。新增编辑不改变1.x入口；未完成正式配套不宣称上线。回滚为SDK包/平台原组合，禁止现场数据回退。

首部并行回归还暴露补正校验的可达性遍历漏掉parallel/join：合法的后续退回源被误判不可达。遍历补齐分支和汇合后继，严格回放目标与禁止正向进入补正节点的规则仍保留；此项会改变共享校验器摘要，后续平台须正式配套，不能只发前端包。

验收：首部连续插入、多补正、非入口插入、首部并行、首节点删除、原错误目标不被静默修复及源对象不变；实际画布新增首节点POST含同步回放目标，原后端严格校验通过。鼠标消失独立调查：目前SDK/应用没有cursor:none或pointer lock证据，不预判根因；记录进入、拖动、释放、失焦恢复的实际浏览器cursor状态，缺少真实PC证据时不宣称已修复。
