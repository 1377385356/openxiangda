# 开抢进入页面：运行时初始化与同身份刷新恢复

状态：2026-10-02，实施及候选验证记录。对应平台编排主题
`2026-10-02-realistic-burst-runtime-and-queue`。平台主题负责读入口预算、
静态资源传输及队列容量；本文只定义 V2 浏览器 SDK 的恢复边界。

## 证据与能力归属

`openxiangda` 2.34.3 的运行时初始化通过现有 `authz/current` 读取身份，
只读请求最长十秒，仅处理权限投影暂未就绪的 503；明确入口繁忙的 429
会直接结束初始化。焦点与可见性检查目前先清除最后验证身份，再发起刷新，
期间已有受管读取可能误判身份变化，停止原申请的结果恢复。

平台始终拥有登录、身份、授权、环境和业务结果。SDK 只等待现有 current
读取并保存平台已经验证的身份，不建立第二个 bootstrap 接口或授权缓存，
也不把 HTTP 等待当成队列受理。本文不证明任何开抢并发人数；最终容量
由同一候选下的完整页面进入、提交及自然结果轮询实测。

## 不变量及影响契约

- 初始化与刷新共用 `loadRuntimeAuthorization` 的唯一挂起 owner。
  同一应用环境的调用、focus 和 visibility 检查合并同一读取。
- 只在返回经过验证的 active/unassigned 上下文后替换身份；临时检查不先
  清身份。401/403、退出、真实用户/环境/权限作用域变化使旧 client 失效。
- 旧代次或取消的响应不得重新恢复退出前的身份。
- 初次初始化与焦点刷新均保留退出通知的优先级，旧 Abort 回调不得把已安装的
  401 登录入口覆盖成临时故障页面。
- 初始化恢复不用于 enqueue、accept、cancel、登录等写入；不创建新业务请求键，
  不变更持久申请原期限、自然三十秒结果轮询提示或现有抖动。
- 普通 Data API、应用 API、V1 分发和 V1 业务保持现有行为。
- `loadRuntimeAuthorization` 增加可选 `AbortSignal`；既有不传 signal 的调用
  保持兼容。信号取消当前调用的观察，所有观察者退出后取消共享读取。

## 等待、失败与资源边界

仅运行时 current（部署运行时与连接开发对应的 current）使用以下策略：

1. 429 `CONCURRENCY_BOOTSTRAP_BUSY` 与 `CONCURRENCY_API_BUSY` 且未明确
   `retryable:false` 时恢复。保留 `Retry-After` 和 `retryAfterMs`，等待不得短于
   服务端提示；指数基准二至三十秒，并加零至 25% 抖动。
2. 整次初始化或刷新截止三百秒，最多一百二十次读取尝试。每次只读 transport
   有十秒预算；整个截止先到时取消 transport。截止不随繁忙、网络或刷新重置。
3. 安全只读的传输失败或本次读取超时最多三次总尝试，仍使用退避；业务拒绝、
   401/403、版本拒绝、未知 429 和非繁忙依赖 503 不扩展恢复。
4. 保留权限投影 503 `OPENXIANGDA_AUTHORIZATION_PROJECTION_NOT_READY` 的
   250/750/1500 毫秒与最多三次恢复；同一投影读取链的十秒限制保留。
5. Abort 立即结束当前调用的观察。一个调用取消不得取消仍有观察者的共享 owner；
   最后观察者退出时，在一个微任务内确认无人接管后停止请求与定时等待并淘汰 owner。
   同一提交中的短清理、重挂载可接管原请求，不能重置读取预算。
6. 读取期间最多一个 owner、一个 transport、一个退避 timer，不留后台无限轮询。
   已成功上下文仍由原 owner 缓存，明确刷新建立新读取；并发刷新合并挂起读取。

平台入口 HTML 的繁忙等待页使用 `sessionStorage` 中当前 pathname 的
`oxa-entry-wait:` 原截止。SDK 仅在 current 真正验证成功后删除当前路径的记录；
失败与单次重试均不改写截止，其他路径的记录保留。存储受限不会阻断成功初始化。

只读恢复中传输失败最多允许两次额外恢复；收到繁忙响应不重置此计数。
整个一百二十次及三百秒边界仍覆盖所有恢复。原异常类型、请求诊断与中文
展示保留；等待 UI 说明正在连接/等待，不声称已经报名。

## 身份刷新、竞争与安全

同身份刷新保留业务页面和未保存输入，受管 client 在等待期间继续使用最后
经过平台验证的身份；每次实际请求仍由服务端授权。返回真实作用域变化后，
原 managed client 的读写都拒绝使用旧作用域。focus/visible 事件与其他 current
调用共享 owner；组件卸载取消自己的订阅并清理事件，不制造新的业务提交。

刷新失败为权限或版本/环境拒绝时清身份并显示失败入口；临时网络或依赖失败
允许保留最后验证页面并明确提示重新检查。恢复原申请时读取原不可变请求键，
不清除 durable intent，不自动重新受理。跨用户 intent 仍由现有 scope 隔离。

SDK 不扩大跨租户缓存、不暴露凭据，不改变用户提供的队列输入如何绑定真实 actor。
官方独立测试主体与完整浏览器请求图由平台/压测工具负责；未来 typed cohort CLI
尚未发布，本文不把它作为已实现能力。

## StrictMode 候选验证及 owner 释放

候选 `8bda030` 的正式 packed 浏览器矩阵收集到 166 项通过、六项既有条件跳过、
一项失败。角色并集用例的三个受保护调用仍没有 Perspective；失败在单次初始化
读取断言：实际两个 current GET 相隔约 0.1 毫秒，首个被取消，第二个返回 200。
官方模板使用 React.StrictMode，其 effect 的同步清理、重挂载触发了最后观察者
立即销毁 owner 的边界，属于 SDK 初始化重复读取回归。

观察者的取消仍立即拒绝自己的 Promise，并使该观察者的完成回调无效。共享 owner
的释放延后一个微任务：若同一提交中已有新的观察者，不取消原请求；若仍无人观察，
取消原 transport/等待并推进代次。安装 current 身份前还须确认同一 owner 仍有活跃
观察者，防止响应在这个短释放窗口安装无人观察的身份。退出和应用/环境作用域变化
继续立即推进代次、取消 owner，不使用释放宽限。

这不是请求重试或延长恢复预算；同一 owner 的三百秒截止、尝试数和原请求继续使用。
保留原角色并集测试的单次读取断言，并验证短重挂载、真实最后观察者取消、已取消
刷新不能替换最后验证身份，以及退出与作用域切换的原有拒绝路径。

## 可证伪验证与回滚

- 用明确 429、服务端等待提示、传输失败、投影 503 和无响应请求验证退避、
  三次传输上限、投影旧边界、截止与取消，确认未知拒绝不重复发起。
- 并发初始化只发生一次 current；取消一个观察者不影响另一个，最后取消后
  late response 不安装身份，退出后 stale response 同样无效。
- 同用户/同 scope 刷新时受管原请求键可继续查询；真实 scope、用户变化与
  401/403 后旧 client 不再发出读写；写失败不重放。
- 浏览器以 focus+visible、同用户输入、真实切换、忙碌启动、键盘重试核验页面。
  本地 focused 测试和 `pnpm verify:affected` 后由编排者统一候选与发布门禁。

改动独立于数据库迁移和队列账本，可回退 SDK 包并重新冻结应用前端；平台
入口预算应保留兼容错误契约。回滚不删除已经受理的命令、请求键、结果或证据。
