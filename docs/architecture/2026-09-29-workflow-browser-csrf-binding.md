# 工作流浏览器请求的 CSRF 绑定

## 证据与所有权

真实预发布：同一审批人读取同一流程封面缩略图，无 CSRF 头返回 `WORKFLOW_V2_CSRF_INVALID`，带当前头返回 200。SDK 附件元数据/Blob 读取遗漏请求头。任务审批出现一次 403；服务访问日志确认该失败，但未保存原响应错误码，不将其断言为某一错误码。

SDK 可重复的独立缺陷：任务详情按 A 头获得一次性 commandToken，另一个调用刷新登录面后全局 CSRF 变为 B；执行原操作时 SDK 重新读取 B。服务器准确绑定 actor、会话、环境、命令集和 A 的摘要，因而应拒绝。这由 fetch 合同测试验证，不代替线上审批验收。

## 修复与不变量

- 工作流附件预览/内容请求使用 SDK 获取的 CSRF 头；预览图继续经授权 Blob，不将 token 放 URL，不放宽服务端文件/字段/实例授权。
- SDK 内存保存每个已签发 commandToken 对应的请求 CSRF，后续执行同一 token 使用原绑定；不把凭据加到公开 Surface 或持久化。按过期时间清理、有界存储，登出失效清除。
- 新加载的 Surface 使用新的 CSRF。未知外部 Surface 保持已有取当前 CSRF 行为，服务端仍是最终权威。
- 失败不得自动换 token、自动重新审批或丢弃原请求事实；保持原 Surface，弹窗明确显示失败。失效需用户刷新后重新确认。

## 验证与回滚

合同测试覆盖任务/实例/关联记录详情、登录面轮换后的原 token、文件元数据/缩略图、403 不降权重试。公开包补丁通过官方 Changeset 发布。回滚仅回退 SDK 包；无数据迁移、权限扩大或服务端变更。上线后仍需真实审批一次、任务状态与业务状态回读、失败提示及封面预览验收。
