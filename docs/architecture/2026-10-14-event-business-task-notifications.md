# Event-owned business task notifications (2026-10-14)

User authorization: implement the five missing ZJNU booking/research pending tasks. This is a reusable V2 platform contract, not a customer task engine.

Evidence: Hub already persists action_required/terminal states and closes external todos; EventBusinessNotificationSendV2 deliberately excludes action_required. Existing pending helper is offline only. Merely widening its enum would let any standard notification subscription create actionable tasks.

Owner/invariants: the application Native transaction owns business state and its immutable task transition event; the platform owns notification message, recipient bindings, outbox, task-center projection, provider effects and receipts. Business handling always opens an authenticated declared APP_ROUTE and invokes existing permission/CAS-protected application operations. This contract grants no workflow commands or interactive callback tokens. No new task database or identity store.

Contract: additive event-task-send/v2 endpoint and Nest facade. Only an active signed event delivery from a current sealed subscription with notification.mode=business-task and explicit taskCodes can call it. Task code, stable business record key, generation, sequence, state, recipient IDs and presentation come from the stored event projection; a body cannot inject recipients or free message/idempotency keys. Platform derives keys from application scope/task/record/generation and event ID. Each new task round has a new generation. Terminal effects only close that original round; a later approval/result cannot reopen it. Standard event notification API remains informational/result-only.

Failures/concurrency: business state and event append commit together. Consumers retry original event/key; stale sequences are ignored by the existing Hub. Out-of-order terminal before creation stays terminal. Rejection/withdrawal/cancellation close pending messages. Recipient lists freeze at task creation and terminal intents retain them. Metadata/lease/Head changes fail closed; quota and bounds use existing Hub. Provider unknown results are reconciled, never replaced by a new send key. Historical imports use triggerAutomations=false and are never bulk notified.

Bounds/security: max16 declared task codes, existing100 recipient bound, projected key<=200 chars, generation<=80 chars, positive safe integer sequence,512 title/2048 summary, authenticated APP_ROUTE only, no requestedActions. New capability notification-hub-v2.event-tasks 1.0.0 lets preflight reject old platforms. Stable V1, ordinary CRUD and other tenants are unchanged; explicit opt-in is required.

Rollback: pause task subscription before removing API; keep all original messages, terminal states, business records, events and receipts. Disable external school channel except an explicitly authorized scoped test. No historical message replay.

Verification: compiler rejects missing/invalid task allowlist and old platform capability; middleware and authorization reject user/OAuth-only/inactive delivery/wrong scope/standard mode/undeclared code; Hub lifecycle tests cover create-complete, reject, cancel, duplicate, terminal-first, stale and new generation. Real PostgreSQL tests preserve exactly one original message/external binding. Nest tests require event context and propagate environment/headers. App tests cover all five pending types and actions leaving/reentering them, Native transaction/outbox atomicity and actual original page navigation. School TEST and live provider tests remain separate gates.
