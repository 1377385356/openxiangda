# Owned 子表提交下限

状态：2026-10-07 实施决定。单一主题：可选 `subtable.minRows`。

## 问题与所有者

业务表单常有至少一行、恰好一行的要求。现有声明只有 maxRows，应用只能重复
JSON Schema/服务校验，标准表单也不能解释下限。模型、Surface、Native owned
mutation 与流程任务仍各由既有平台组件拥有，不建立另一份关系或授权目录。

## 稳定不变量与影响

minRows 可选，默认0，整数0..DATA_SUBTABLE_MAX_ROWS，且不超过 maxRows（默认20）。
与 maxRows 一样约束父表提交的 owned 子表计划，不是任意独立子资源 CRUD 的全库
聚合约束。应用仍关闭 owned 子表独立写权限。普通父表 create 的下限即使省略字段
也执行；update 仅校验显式提交的表；未提交表不产生隐式写入。

审批补填/草稿可暂不足，完成任务时对可见可写表的最终 live rows 检查下限。
删除标记不算live，替换、顺序、身份、revision 和字段校验不放宽。只读/隐藏表及
历史固定声明不因新UI补造行。下限不要求每个子字段必填，空行仍受各字段声明控制。

类型、公共JSON Schema、Native ESM/CJS编译、Surface、SDK表单及Server计划同步。
显式正下限需要 `data.subtable-minimum-rows@1.0.0`，不新增关闭默认功能的开关。
无正下限声明无需此能力。稳定1.x与其他应用不变；旧固定版本保持原定义。

## 失败、并发与边界

不足在规划阶段返回稳定错误，事务执行前失败，不留下父/子半写入。现有父/子
锁、CAS、原key恢复、2MiB和总行数预算保持；下限不能提高上限或授权范围。
UI显示下限；普通编辑不能删到下限以下，任务可暂删以保存未完成草稿，完成校验
反馈明确行数。UI不自动生成可信业务资料，应用可声明初始空行。

## 回滚与可证伪验证

新字段为增量契约。回退前停止含正下限的新声明激活，保留数据/原key/任务历史；
旧Server必须兼容性拒绝，不能忽略下限。旧声明、未改表更新和草稿回归；两格式
编译拒绝负数/小数/大于max；父表省略/空表/全删均拒绝、同事务一行替换成功；
任务草稿不足可存，完成无输入也检查当前行，隐藏/只读不反向修复历史；PC/手机
实际表单验证和B11批次运行作为独立运行证据。源码测试不算正式制品验收。
