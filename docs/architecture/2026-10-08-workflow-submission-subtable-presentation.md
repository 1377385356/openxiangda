# C80 具名提交的子表展示规则

状态：实施；范围为 V2 根 SDK 的具名新建表单，不修改流程引擎和权限契约。

问题证据：YWTB-074 V12 的 08 业务解释 L9 要求“附中报考”只显示附中事实，
大学/空类型显示其余四项，五事实的已有值必须保留。当前根表支持 fieldState，
SubtableField 的 launch 仅支持字段闭包和只读列，PC 与手机会显示全部五列。
来源在网上办事大厅审计，不将学校字段编码内置到 SDK。

应用页面拥有展示条件；平台与 sealed ownedSubject 仍唯一拥有子表读写和数据。
新增 formOptions.subtableFieldState，输入为当前规范根表值，输出为按子表/列的
visible、required 布尔状态。只允许匹配具名提交的现有子列；不能引入新表、系统
字段、只读写权限、hiddenValue 或任意配置。required:false 不撤销已有必填。
隐藏仅移除显示和前端校验，不改 row.data，重新显示恢复原值；提交仍沿现有
namedProcessFormValues 的闭包编码和服务端验证。源隐藏required如何运行仍未核实，
应用需明确其目标校验策略，不能宣称 SDK 改变了源业务约束。

规则错误阻止新提交，不部分应用。PC 表头/单元格与手机行和全行验证使用同一
展示事实；分页、文件、异步编辑、原命令恢复和授权不变。状态只在当前表单内，
没有持久配置或并发权威。父字段切换不删值；限制由已有子表容量和字段闭包保持。

回滚删除可选 formOptions 配置即可恢复全部列；已有申请不迁移。稳定 1.x 不引用
V2 实现，其他 V2 表单无该选项时行为不变。验收须证明隐藏/恢复保持原值、不能
扩权、隐藏行不参与可见校验、重新显示后必填生效，并在真实PC/390px表单操作。
