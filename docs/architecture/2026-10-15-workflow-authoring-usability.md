# 工作流画布可理解性与完整验收

## 问题与依据

合同应用用户要求统一完善画布、中文变量/参数、AI 改图、部门主管等审批人类型及真实页面验收，并优先本地验证。现场首节点新增的回放入口不同步已在 2.70.2 修复；真实首节点保存、鼠标和角色验收仍不能以发布成功替代。当前人员编辑器将复杂的已发布来源藏在“其他人员来源”，且展示 binding 英文编码，使已存在的部门主管能力不可发现。

## 所有者与不变量

- 平台拥有人员解析、授权、目录、草稿、发布、原命令恢复和在途快照；应用拥有已声明的规则与中文说明。
- 本增量先统一展示人员类型、已发布规则的中文参数摘要；类型切换只选择目录中的精确规则，不能从显示文案构造新 provider 或扩大人员范围。
- 已发布来源的 level、fallback、min/max、scope、变量路径保留原字节语义；渲染不触发修改，无目录项的类型不冒充可用。
- 每个来源必须同时说明部门/表单事实、主管级别、无人处理方式及人数约束。绑定编码仍为内部稳定标识，不作为用户的选择标题。
- 后续变量选项、主管参数编辑和 AI 改图按原已授权完整目标分别补齐验证，不以此展示修复缩小目标。

## 边界、失败与资源

此主题仅 SDK 展示，不修改后端权限、schema、数据库或 V1。目录最多沿用平台已返回的有界集合，不增加请求或全量人员读取。未知来源保留原值并提示，不自动选人；禁用状态不可修改。选择明确类型是用户输入，后台解析和人数检查仍失败关闭。在途人员和浏览器未保存草稿不做迁移或自动提交。

## 验收与回滚

- 单元：中文标签不泄漏来源/路径编码；部门与归口部门可区分；主管级别、祖先回退、人数范围均正确；规则深比较仍精确，不修改原值。
- 组件/浏览器：原两种简单类型及部门主管、范围角色、表单成员、连续主管、发起人等目录项按实际存在显示；类型和规则切换只产生一份精确值；禁用、空目录、未知值保持。
- 本地实际 SDK HTTP 夹具通过后，统一正规 npm/平台配套与应用 TEST 发布，再以真实角色验证。数据/几何、synthetic、源包和已部署页面分别记证据。
- 回滚只撤销此展示，不降数据库、不删除来源、不重放审批。完整目标包括 AI 改图、变量便捷选项和全部实际画布功能，未通过前不得标完成。

## 中文条件选项的展示契约（本地待验证）

- 问题：字符串事实 yes/no、specified/skipped 以及合同类别编码目前仅可手输，老师无法判断含义。
- 本增量由应用从现有模型字段 options 传入 `WorkflowDesigner.variableChoices`，SDK 仅添加中文展示与选取；平台事实路径、原始类型、条件表达式、求值、权限和保存协议不变。不在 SDK 硬编码客户变量或由中文反推业务值。
- 候选不新增 definition/schema/backend 字段；元数据不是授权、不是校验上限。最多128变量、每变量64个标量选项，拒绝非法类型/重复值/空文案；不自动规范化未知或旧值，不将数值/布尔字符串化后保存。
- 普通条件、并行条件、条件人员和临时示例使用同一展示辅助；仅精确已知原始值显示标签，未知值提示需明确选择，保持原表达式。`in`按列表原类型还原。不修改正在编辑草稿、业务事实、历史实例或 AI 提案权限。
- 可证伪验证：混合类型/值0/false/重复/过大集合单元；实际组件浏览器从中文选择读回 exact raw expression，未知不触发写入、disabled拒绝修改、条件示例和分支计算一致。此增量未正式发行和现场验收，不能据此声明可用。

## 2026-10-15 本地已得证据与未闭合项

25项实际纯辅助/SSR断言及当前SDK类型检查通过；同一Ego浏览器目标Space5中的实际源码组件交互已验证中文“一般”保存原值no、切换表单成员保留精确字段和人数界限、临时示例按同一值判断、未知legacy不自动修改、禁用和空目录保留原值。浏览器是无HTTP/无真实身份的组件夹具，不是现场完整流程或角色验收。原fixtureCSS入口首次指向未合成的源样式失败，改用正式构建样式后渲染成功，未隐藏Vite错误。

剩余完整目标仍包含主管来源参数范围/完整目录、部门动态选择、首节点真实整图保存与退回重审、鼠标视觉、AI真实模型和应用提交，以及应用正式发行/TEST/真实角色。人员复杂来源的展示与精确选择不等同于允许编辑任意主管参数。新中文选项尚未正式发行，不能称合同应用已使用。
