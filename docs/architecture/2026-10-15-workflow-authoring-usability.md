# 工作流画布可理解性与完整验收

## 问题与依据

合同应用用户要求统一完善画布、中文变量/参数、AI 改图、部门主管等审批人类型及真实页面验收，并优先本地验证。现场首节点新增的回放入口不同步已在 2.70.2 修复；真实首节点保存、鼠标和角色验收仍不能以发布成功替代。当前人员编辑器将复杂的已发布来源藏在“其他人员来源”，且展示 binding 英文编码，使已存在的部门主管能力不可发现。

## 所有者与不变量

- 平台拥有人员解析、授权、目录、草稿、发布、原命令恢复和在途快照；应用拥有已声明的规则与中文说明。
- 本增量先统一展示人员类型、已发布规则的中文参数摘要；类型切换只选择目录中的精确规则，不能从显示文案构造新 provider 或扩大人员范围。
- 已发布来源的 level、fallback、min/max、scope、变量路径保留原字节语义；渲染不触发修改，无目录项的类型不冒充可用。
- 每个来源必须同时说明部门/表单事实、主管级别、无人处理方式及人数约束。绑定编码仍为内部稳定标识，不作为用户的选择标题。
- 后续变量选项、主管参数编辑和 AI 改图按原已授权完整目标分别补齐验证，不以此展示修复缩小目标。

## 边界、失败与资源

此主题仅 SDK 展示，不修改后端权限、schema、数据库或 V1。目录最多沿用平台已返回的有界集合，不增加请求或全量人员读取。未知来源保留原值并提示，不自动选人；禁用状态不可修改。选择明确类型是用户输入，后台解析和人数检查仍失败关闭。在途人员和浏览器未保存草稿不做迁移或自动提交。

## 验收与回滚

- 单元：中文标签不泄漏来源/路径编码；部门与归口部门可区分；主管级别、祖先回退、人数范围均正确；规则深比较仍精确，不修改原值。
- 组件/浏览器：原两种简单类型及部门主管、范围角色、表单成员、连续主管、发起人等目录项按实际存在显示；类型和规则切换只产生一份精确值；禁用、空目录、未知值保持。
- 本地实际 SDK HTTP 夹具通过后，统一正规 npm/平台配套与应用 TEST 发布，再以真实角色验证。数据/几何、synthetic、源包和已部署页面分别记证据。
- 回滚只撤销此展示，不降数据库、不删除来源、不重放审批。完整目标包括 AI 改图、变量便捷选项和全部实际画布功能，未通过前不得标完成。
