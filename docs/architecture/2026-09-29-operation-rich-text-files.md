# 具名动作富文本插图与开发态附件授权

## 问题与所有者

应用活动编辑使用标准 `text.rich`，但 SDK 的作者配置和 Native 编译器只允许 `managedFiles` 绑定 file/image/signature。平台上传与富文本引用解析已有 text.rich 支持。这是平台声明闭包缺口，不能让应用借用封面字段上传。

Connected Dev 的服务层读取可信 overlay，而记录上传的 PostgreSQL RLS 仍仅接受已发布动作。开发态更新已有记录因此返回记录不存在。该问题由平台后端修复，不能开放业务资源普通写权限。

## 不变量与最小变化

- `managedFiles` 的精确资源、字段、create/update 意图和当前动作能力不变；仅允许新增 text.rich 字段类型。
- 富文本图片仍使用平台托管文件、同字段绑定、内容类型和大小限制，以及既有渲染清洗规则；外部图片地址、跨字段复用不在本变更范围。
- 开发态会话由平台逐请求验证身份、租户、预发环境、当前 Head、授权版本和有效期。内部生成的有界附件证明供数据库校验，仅授权本次指定行的文件字段读取。客户端不能提交证明、overlay 或姓名身份事实。
- 已发布动作沿原授权分支；生产环境、普通 CRUD、工作流及其他租户权限不扩展。
- 新增 expand 迁移，保留函数 OID、ACL 和现有分支，不改历史迁移。回滚应用版本不会删除业务文件或数据；撤回平台修复时恢复前一函数定义。

## 可证伪验收

作者配置和 Native 编译应接受具名 text.rich 上传绑定，拒绝普通文本及错误字段。服务测试需覆盖可信开发声明、失效会话、精确字段和意图；真实 PostgreSQL 需验证开发态已有记录上传可读，过期、生产环境、错行、错字段、错误操作及混合证明拒绝。应用上线仍需真实上传、提交富文本绑定和图片读取证据，源码测试不代替该验收。
