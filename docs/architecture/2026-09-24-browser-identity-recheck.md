# 浏览器跨标签身份重核

日期：2026-09-24
状态：实施候选（PL-31）

## 问题证据与能力所有者

合同管理预发同一 Chrome Cookie 在另一标签改以经办人登录后，旧 SPA 仍展示“系统管理员”和接口消息入口；服务端按当前经办人正确返回 403，另一旧页点击“我创建的”返回 401 `Token is invalid`。OpenXiangda 浏览器运行时缓存成功的 `runtimeAuthorizationLoad`，只监听平台退出广播。平台当前授权接口仍是唯一身份和能力事实，不创建应用侧会话副本。

## 稳定不变量与行为

- 应用标签重新获得焦点或从隐藏变可见时，向当前应用/环境的 `authz/current` 做一次只读重核。`refresh` 先失效内存身份与已缓存的授权 Promise；并发只读请求发现作用域变化后自行失效。不得自动重放任何写请求。
- 重核期间用不可关闭的遮罩阻断旧页面输入，保留组件树与未保存表单。主体、环境或 `identityScope` 均未变化时更新授权上下文并移除遮罩，不重挂应用组件；权限集合的增减由新上下文即时生效。
- 主体或作用域变化时立即卸载旧页面并显示“身份或权限已变化”。只有用户显式继续才挂载新身份；旧未保存内容不跨身份提交。`unassigned` 和 401/403 仍走已有禁止访问/登录分支，不扩权。
- 退出广播优先于在途重核结果；失效序号使旧响应无法恢复退出后的旧页面。公开匿名页面不触发该检查。

## 资源、安全与回滚

每次重新聚焦最多一条授权只读请求，焦点/可见事件在飞期间合并；无定时轮询。失败显示既有错误或登录界面，旧组件不继续可操作。稳定 1.x SDK 不受影响；其他 V2 应用只在重获焦点时增加同源只读检查。回滚至前一 SDK 包版本不涉及数据迁移，但会恢复旧页面漂移风险。

## 可证伪验收

同身份重核期间原表单保持挂载且不可提交，结束后未保存输入保留；跨标签切换为另一主体后旧角色菜单和旧表单不再可见，新主体需显式继续；旧重核与退出广播竞态不能恢复旧页面；无授权或 401/403 均不能继续旧身份操作。具名预发管理员↔经办人各测试一次，且不授予经办人接口消息读取权。
