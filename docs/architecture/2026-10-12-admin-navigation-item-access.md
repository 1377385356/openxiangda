# Independent admin navigation item access (PLT-053)

Status: implementation topic, not published or school acceptance. SDK writer is
/home/yuxing/lowcode-main/openxiangda-navigation-item-access-wt, branch
codex/admin-navigation-item-access, based on 3a1afece. The active publication
worktree is not edited. This topic affects contracts/devkit/openxiangda public
packages and needs a new reviewed SDK release; its changeset does not version
or publish the current frozen train.

Evidence: V1 school management has 19 C/D deep-link entries including notices,
but only 18 visible menu items. Current item declarations/contracts have only
page/label/icon/order, and the browser filters menus with page authorization.
Granting the page UI capability therefore also exposes the menu.

Owner/invariants: the platform owns current capability facts and role unions.
Add optional navigation item access using the existing allOf/anyOf capability
expression. Navigation visibility is page access AND item access; page/deep-link
permission ignores item access. Default entry must choose a visible allowed
item. No browser role cache, customer-specific filtering or new permission
store, no data/action/membership grants and no RLS changes. Existing navigation
without item access preserves its generated bytes and behavior.

Contracts: source item and generated item gain access; local and shared native
compilers validate bounded expressions and declared capability closure, and
include normalized access in generated adminNavigation. A new opt-in formal
platform capability application.admin-navigation-item-access@1.0.0 is required
only for declarations that use it; older platforms fail before deployment.
A platform advertisement must be integrated with the newly published shared
compiler, not deployed alone over the old vendor package. Version changes and
vendor/lock pairing belong to the release agent.

Runtime: the platform-authorized current capabilities feed both menu filtering
and default entry through one item+page predicate. Resource page requirements
and operation route closure remain required. Runtime identity refresh/revocation
reevaluates the projection; item access does not grant page or business access.
The UI layer may hide a route from menus while the original page route remains
addressable and protected independently.

Failure/concurrency: malformed/empty/duplicate/unknown expressions are rejected
with a pointer by both compilers; normalized arrays are immutable in runtime
navigation. No new HTTP/DB endpoint, side effect or queue. Bounds remain 50
capabilities per anyOf/allOf, existing menu item/group limits. No dynamic roles
or application-dependent platform exceptions. V1 is unaffected.

Verification: local/shared ESM+CJS compiler parity and byte closure; malformed
capability references; menu false while deep link true; menu-only capability
cannot make an inaccessible page visible; default-entry respects hidden items;
current capability revocation and anyOf/allOf; omitted access unchanged;
platform capability requirement off/on; SDK check/build and affected tests.
Application adaptation is handed to root: notices page UIcap to original S/C/D,
separate navigation UIcap to original S only, attached solely to its explicit
navigation item. No extra notices data/actions. Root performs publishing and
school role/browser acceptance.

Rollback: remove opted-in item access from the application and restore its prior
explicit navigation/page grants through normal reviewed releases. Old SDKs
cannot consume declarations that use the new feature. No data migration.
Parent-reference PLT-052 remains separate.
