# 流程画布编辑与保存一致性修复

## 证据与范围

用户现场请求在已发布定义上新增审批节点后，draft 保存返回 DOCUMENT_INVALID。本地使用同一请求和官方 Ajv schema 重现：唯一 shape 错误为已有 readability 被顶层 additionalProperties 拒绝，新增审批节点和 binding 通过。编译器和类型已正式支持 readability。真实双连续条件路由在 layoutDesignerRegions 中复现两条边终点与目标节点相差数百像素：前一区域把后一区域的 fork 当作 join 共同占有，布局节点被覆盖而路径保留旧坐标。

同时用户要求画布默认不展示流程大纲或节点配置；应用后台列表点击进入独立画布。通用布局、编辑器交互及正式 schema 归 SDK；合同应用页面/路由由应用唯一 writer 维护，不写入 SDK 业务定义。

## 不变量与决策

- 仅修复显示投影的所有权：结构区域拥有 fork 与内部节点，汇合目标保持外部单一节点，区域出口与外部路由拼接。相邻条件/并行区域不得重复拥有同一节点；不修改 canonical graph、条件、顺序或执行边。
- 大纲通过按钮开启临时面板，关闭后无图标轨道常驻；节点配置初始关闭，通过选择节点打开浮层，关闭/切换保留现有 dirty、busy、unknown 保护；不持久化新的全局偏好或引入移动画布。
- readability 纳入既有 closed schema，与正式语义校验相配套，保留 label/logic/source 的边界和 code-owned 保护；不删除现场 readability，也不放开任意属性或更改审批权限。
- 服务端必须消费正式 contracts 发行后才宣称保存修复上线。源码修复、npm、平台及应用部署分别验证；不使用临时 shim、直接 SQL 或用户粘贴 Cookie 操作现场。
- 并发和失败保持原 operationId/CAS/草稿保留，不自动发布、重试不确定请求或换 Run。V1 不受影响；V2 对合法元数据为增量接受，其他租户流程拓扑不变。
- 回滚按 SDK/平台/应用原版本分别回退；新代码不写迁移或历史业务记录。本次不包含此前保留但未发行的 recovery ack。

## 可证伪验证

用脱敏、业务无关的相邻条件路由（含空分支、连续任务、后续节点、节点插入）验证每条路径起终点等于实际节点端口、全部正交、节点无重复/重叠、输入图不变；保留嵌套条件/并行回归。正式 schema 验证已发布 readability 加新增审批的保存文档，未知/超限 metadata 拒绝，code-owned logic 不可变。浏览器验证默认两面板关闭、按需打开/关闭不挤压画布、未保存输入和权限撤销保护、插入节点完成草稿保存。
