# 事务内资源快照引用

## 问题与所有者

真实应用首次创建主记录和引用它的关联条目时，原输出缺少资源快照的 resourceCode，并且公开 validateDataTransactionRequest 即使补齐资源字段也会将所有嵌套 operationIndex 引用拒绝。服务端 Native Data API 从 57a162826 已支持严格 resourceCode/label/value 资源快照，普通字段验证器仍要求资源快照，故不能将关联字段改成裸主键引用。应用公开请求探针已保留首次班日失败及其余八种代表动作的输出；不是现场身份或真实写入证明。

共享合同拥有可序列化的请求形状与预检；Nest 只提供构造助手；平台继续生成主键、解析前序结果、校验字段/引用/组织/授权并原子提交。应用不预分配主键、不拆事务、不修改生成物或以原始 UUID 绕过资源字段。

## 不变量与实现

保持直属 {operationIndex,field:'id'} 原合同；仅额外允许字段直属的资源快照，其 value 是一个指向之前 create 的 id 引用。必须保留字面 resourceCode 和 label，仅允许既有快照元数据键；resourceCode 必须与目标 create 的资源一致。引用只在 value 这个明确位置，其他对象/数组/快照元数据中的引用仍拒绝；指向自己/将来/非create、额外键和非整数索引拒绝。

导出资源快照事务值类型，并为现有 resourceSnapshot 添加重载；字符串主键调用保持原返回类型。不是新的权限或执行模式，不改变普通快照写入、V1 路径、幂等域或同事务失败回滚。共享规则和源文档随精确版本发行，目标平台按新合同 seal 配套；不在应用里补丁 npm 包。

## 失败、并发、资源与回退

预检失败在发请求前返回原诊断。平台主键解析及引用读取沿用当前事务锁和隔离，任何字段/授权/引用失败全部回滚，原键查询已提交结果；新助手不自动重试。不增加嵌套深度/操作数/消息字节预算。新增允许形状不授予字段写权限；label和snapshot仍是显示事实。

源码和 tarball不可变，发布/平台/应用运行独立记录；若回退 SDK，新的资源快照引用重新被旧预检拒绝，保留原业务回执并向前修复。没有数据迁移或密钥变更。

## 可证伪验证

先用公开验证器复现合法资源快照引用被拒绝，再覆盖合法直属/资源快照、全部边界与伪装嵌套；Nest构造的真实事务交给同一公开验证器。应用全部动作以真实服务输出校验公开合同。平台保留其实际解析及字段验证测试；正式候选、npm读回、002配套和新应用TEST另验。真人钉钉、第二学校及浏览器业务验收不足时保留未覆盖。
