# Return policies and guarded resume

Approved design: Claude P1 execution review, 2026-10-11. The canonical workflow owns a bounded returnPolicy on approval/handle nodes: targets by stable nodeId, permitted replay/resume routes and defaultRoute. An initiator target is an existing published correction node. Legacy returnTargets remain readable; when both are present their target sets must agree. The canvas and assistant share validation and remove dangling targets when deleting a node.

The existing kernel, task ownership, return sessions, facts, step receipts and RLS proof remain sole owners. Return reads routing policy; offered actions and form rules remain entry-owned. Invalid or unvisited targets and disallowed modes refuse. Applicant resume changes all kernel replay-only guards together with the SQL original-initiator proof; identity, token, assignment and field checks remain intact.

Resume re-evaluates the current route from the corrected target to the returning source using refreshed facts. Conditions use the existing evaluator. An encountered business step may only be skipped when a completed execution has the same handler version and canonical mapped input digest and a verified stored output; unknown or changed inputs force replay with a recorded reason. No handler is invoked by the guard. Successful resume appends closed visits with status skipped and an evidence visit pointer with return-resume evidence, then enters the source as a new task. Eligible returners are preferred only for single/any; all/sequence use the node's full currently resolved set. No automatic completion on return-review/resume/correction.

Concurrency/idempotency: the original command transaction and instance/configuration locks protect guard evaluation, task closure, skipped visits and the new task. Original command receipts absorb retries. Bounds remain 200 transitions, 20 targets, two routes; no new credential, privilege or external side effect owner.

Compatibility/rollback: legacy policies keep old defaults, including correction replay-only until explicit resume policy is configured. V1 is unaffected. Keep new route/session evidence and the coordinated RLS reader during source rollback; do not erase visits or replay unknown effects. New capability negotiation prevents use with old servers. No production release is included.

Verification: A-B-C replay A-B-C-D versus resume A-C-D; applicant correction resume; changed conditions or step inputs fall back to replay; unchanged outputs are reused without execution; eligible single/any returner, full all/sequence set; entry/R routing and SQL original-initiator rejection; per-target UI defaults; denied modes and stale tokens.

Claude refinement: an interior target resumes/replays from its current successor; only applicant correction starts at the workflow start. Evidence is restricted to the immediately preceding target-to-source traversal, with transitive return_resume evidence pointing to a real completed visit. Empty-approver skips are not evidence. Guard-written visits use status skipped and never create tasks, participants or handler notifications. A later return edge cannot reorder an earlier timestamp group into a fabricated cycle.
