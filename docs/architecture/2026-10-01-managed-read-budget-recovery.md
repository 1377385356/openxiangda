# 受管只读预算繁忙恢复

状态：实现候选，2026-10-01。主题仅覆盖 SDK 读取与持久观察，不改变平台配额、身份、命令处理或入队权威。

问题证据：高峰时期服务端工作预算会主动拒绝部分读取。原 SDK 的详情首次读取及 mine 查询直接失败；持久结果观察又对任意 503 或网络失败反复等待，使真实依赖故障不易识别。工作预算、传输恢复与业务等待需要分别拥有边界。

能力所有者：平台拥有授权、限流预算、原命令与最终业务结果；SDK 只负责原请求的有界只读恢复。仅 read、mine、result、allocation 使用共享读取恢复，写方法单次调用不重放。持久控制器继续独立管理原键入队恢复，只有明确提交或恢复才允许写入。

不变量：完整参数和应用/环境/主体/权限视角在一次读取内冻结；身份变化停止，不能切换到新主体。读取默认总预算120秒、最多12次总请求，服务端提示与指数抖动控制等待。只有已知预算429和兼容的已知预算503可恢复，依赖、权限、未知错误不能变成繁忙。硬请求截止使用AbortSignal及竞态中止，不依赖传输一定实现取消。返回最后busy只代表该次读取未恢复，不代表业务失败。

持久时间边界：acceptanceRecoveryMs继续只控制入队，默认120秒。已受理自动观察最多首次明确提交后30分钟；跨设备以原acceptedAt计算，刷新不续期。每次读取缩窄为原剩余时间和120秒的较小值；等待无法落在原窗口时停止。迟到的明确查询可以取回终态，但不能重新启动到期自动观察或再次入队。时间倒退、无效回执时间不扩展窗口。

故障和并发：已知busy耗尽后，持久控制器可在原窗口内退避继续；真实读取故障立即显示并停止观察。核对原结果未得到404时不得再enqueue。组件卸载中止读取与等待，不取消已受理业务。多个同业务观察者仍由应用避免重复挂载；SDK不新增全站单例或跨主体共享缓存。

资源与安全：每次调用硬限时和限次，输入沿用原公开有界契约；没有新的后台依赖、凭据或权威状态。读取错误保留原响应及中文提示。普通Data API、permit写入和其他租户路由不添加通用重试。

回滚：独立回退此SDK补丁恢复原读取行为，平台工作预算和已经受理的命令保持原事实。不删除恢复键、不改业务记录，前端依然可以明确查询原结果。

可证伪验收：真实浏览器展示加载→已知429→正常内容；依赖503只一次并立即失败。单元边界覆盖120秒/12次、Retry-After、输入冻结、权限视角变化、AbortSignal、悬挂传输、原30分钟观察、跨设备年龄、迟到终态及写方法不重放。平台容量及目标应用300/1000/3000用户完整链路由统一候选另行验收，此处测试不声明业务容量。
