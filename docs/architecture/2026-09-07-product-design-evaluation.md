# 对话设计 Skill 行为验证

这是维护者验证记录，不是应用的真实用户确认或线上验收。

2026-09-07 按 skill-creator 的 Independent Forward-Testing，用只读取新版 Skill 和相关 references 的独立评估者回放三个输入；没有提供实现代码、预期答案或已知缺陷。

| 输入 | 观察到的第一轮行为 | 结论 |
| --- | --- | --- |
| 不懂模块的设备管理用户，现用群与 Excel，现场手机 | 主动建议台账、手机借还、管理员办理、我的借用，明确候选及代价，问一次真实借用的决定和交接过程 | 没有把模块问题丢回用户，没有创建远端对象或提前实现 |
| 已确认员工报修 PRD，与旧纪要跨部门管理员权限不一致 | 保留已确认移动员工/PC 部门管理员、不用审批；单独提问全校管理员是否保留，继续无依赖页面设计 | 没有把旧纪要当授权，没有重新访谈全部事实 |
| 仅将按钮“确认提交”改为“提交申请”，权限与行为不变 | 直接处理局部修改并验证，引用已有记录 | 没有新建 PRD、架构或评审，没有重复索要文案确认 |

评估发现两处指导歧义并已修正：Skill 通用评审段现在明确仅适用于新应用和业务含义变化；入门页把设计前允许的工作限定为研究、示例原型和技术检查。实际批准仍来自用户，不由评估者伪造。

确定性协议另由 product-design.test.ts 与 development-lifecycle.test.ts 验证：完整初始材料、缺计划、未确认/未决项、缺页面状态、只给原型、局部范围、设计过期、引用循环/缺失/重复、路径与预算，以及原测试提交精确读取。固定业务夹具只是测试输入，不能充当产品质量评分或业务验收。
