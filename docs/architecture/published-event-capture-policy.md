# 按发布版本确定数据事件捕获

普通 CRUD 的必要成本是业务校验、当前用户权限、记录并发约束以及业务提交。
事件是否需要保存由应用发布契约决定。共享编译器生成不可变捕获计划，平台
按事件、数据、授权三个版本读取同一计划，不使用瞬时订阅数量猜测。

默认保留所有增删改事件。没有完整事件审计或历史回放要求的资源，可显式声明：

```ts
events: {
  subscriptions: [],
  capturePolicies: [{ resourceCode: 'items', mode: 'subscribed' }],
}
```

`subscribed` 仅保存本次发布的订阅声明要求的操作事件。没有 `resourceCodes`
限制的订阅覆盖所有资源；暂时禁用的订阅也算已声明需求。运行时不根据过滤器
是否命中、消费者是否在线或当前积压决定丢弃事件。`all` 或不声明策略均保留
原行为。旧计划摘要不变，新策略要求平台 `events.capture-policy` 能力。

需要的事件与业务数据在同一事务提交；不需要的事件不写事实和 outbox，也不
唤醒投递。权限、租户隔离、字段约束、文件引用、日期触发投影和流程命令独立
保留。自定义 `emitEvent` 不受此策略影响；被捕获事件的载荷语义也不改变。

此模式不提供完整变更事件历史。回放只能使用实际保存的事实。恢复 `all`
只恢复今后的捕获，不能补造未捕获的过去事件。需要完整事件审计或未来任意
历史回放的资源应保持 `all`。数据库的业务审计字段访问权限与事件历史是不同契约。

策略通过正常应用版本发布、测试和生产晋级生效。非法资源、重复策略、未知模式
及损坏计划拒绝执行。不同记录并行；同一记录仍遵守原修订号约束。没有新增连接
池或后台执行器；内部标准动作、后台公平调度和异步日期投影属于后续独立改动。
