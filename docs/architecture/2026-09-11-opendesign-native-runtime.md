# OpenDesign 原生运行时与 CLI

状态：按用户 2026-09-11 的明确要求实施，取代上一轮只分发精选设计方法的默认路径。

## 问题与决定

用户要求“整个 cli 相关都接入”“更好更全面体验他的功能”“没必要做太多改造”。0.22.2 官方 macOS 发行版已经包含完整 CLI、桌面界面、设计资源及受管理的 daemon；许多命令调用原生服务。前一轮的精选文档不是完整产品，不能继续用自制工作台替代上游体验。

默认使用原版 OpenDesign。享搭只提供 `design open/status/cli` 入口、安装发现、原生命令透传和 AppSpec 产物交接指引。上游完整项目、模板、设计系统、插件、预览、检查、导出、运行、MCP 等继续由原版实现。已分发的设计资料作为离线参考，不限制原版能力。暂不为上游每条命令建立第二套 API、MCP 工具或参数模型。

## 所有者与不变量

- OpenDesign 独占自己的安装、更新、设计项目、Agent、运行状态及数据目录；不复制其 SQLite 或配置，不维护另一个 daemon 端口表。macOS 桌面版从已安装包的配置发现 CLI，再调用同一包的 `@open-design/sidecar` 查询当前端口。
- 享搭继续拥有应用业务、平台身份、授权、路由和部署。设计原型通过上游导出/文件功能进入应用的 AppSpec assets；设计工作完成不自动发布应用。
- CLI 参数、标准输入输出、原生 JSON、退出码与中断保持原语义。`cli` 后面的 `--json`、`--cwd`、`--mcp-stdio` 等不能被享搭解释。执行使用参数数组，不使用 shell 拼接。
- macOS 默认发现官方应用；其他安装和平台显式使用 `OPENXIANGDA_OPENDESIGN_CLI`/原生 `OD_BIN`，并用上游 CLI probe 验证身份。不能误运行系统 `/usr/bin/od`。显式无效路径失败，不静默换到其他安装。
- 原生桌面数据/导入授权、云服务登录和外部连接器权限仍遵守原版规则；桥接不伪造桌面 token，不绕过权限，也不把 CLI 的任意写命令伪装成只读 MCP。

## 失败、资源、并发及回滚

发现是只读的；没有安装给出官方发行入口。只有 open 明确启动应用。状态查询限时；配置读取有大小上限；不扫描整盘，不下载或执行最新 main。原版更新仍使用官方发行和更新器，接口变化给出明确错误并允许显式 CLI 路径。运行透传由原版管理锁和并发，享搭不另起调度器。取消转发到当前子进程；保留真实非零码。

本轮只影响 V2 本地开发入口和资料，不修改平台后端或 V1。npm 包不携带桌面二进制。回滚享搭版本可撤销入口；OpenDesign 安装与设计文件保留。回退原版遵循原版数据兼容规则，不由享搭自动降级。

## 可证伪验收

验证真实官方包签名/摘要及版本；原版界面完成本地 Codex 初始化；桥接查询动态服务、列出项目/模板/设计系统/技能、读取设计方向、创建验证项目并用原生 lint/导出；机器测试覆盖丢失安装、伪 od、带空格路径、未知原生参数、stdio、退出码与取消。发布验证对精确 tarball 的全新安装执行入口透传，确保源码通过不冒充发布包通过。应用真实业务发布另行验收。
