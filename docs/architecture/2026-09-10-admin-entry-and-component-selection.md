# 管理后台入口与组件选型

状态补充：2026-09-11 的 [OpenDesign 接入决定](./2026-09-11-opendesign-capabilities.md)已取代本文对默认外观和后台设备范围的限制；平台导航、字段与权限行为约定仍有效。本文保留为历史证据。

状态：2026-09-10 用户已确认本轮优化，并补充“管理后台不需要做移动端适配，都默认管理后台只需要 PC 端操作”。

## 证据与问题
测试 Demo 已声明数据模型，但全部业务页为 user surface，adminNavigation 为空。平台应用列表统一拼接 /admin，运行时又将无后台入口显示成“没有声明数据资源”。模板中的 /home 用户页被直接沿用，自定义报表因此另建顶栏和导航；在用户提醒后才使用 ECharts。

## 所有者与不变量
平台目录只决定环境和挂载根，应用 routeManifest 决定首页与设备入口。后台导航由应用显式声明，平台只渲染和按当前用户能力过滤；模型数量不决定菜单或空状态。平台保留唯一 Router、Shell、身份与授权。图表库负责可视化，平台 Data API 继续负责授权后的聚合和分页。

## 决策与合同
- 后台默认仅 PC。普通管理、录入、报表优先复用平台外壳；自定义报表用 admin operation 页面加入显式菜单，不因“自定义”改用 user surface。
- 需要独立用户体验时才使用 user surface。只有用户端存在明确手机任务时才设计移动页面，不为后台自动补移动副本或移动验收。
- 模板 /home 是用户页占位，不是所有应用的信息架构决定。进入设计/开发时选择页面类型并确认真实启动路径；后台表、页面、菜单分别声明。
- 后台入口继续使用同一权限过滤函数：无导航为未配置；有导航但无可访问页面为无权限；未知地址为不存在。不修改权限或自动创建菜单，也不根据资源数量推断缺失。
- 图表优先评估 ECharts，其他专业交互先评估项目依赖和成熟库。技术选型记录适配性、包体积及维护理由，按需加载并释放实例；不自动安装整套推荐库。

## 失败、并发与资源边界
本轮不增加接口、数据存储、后台任务或请求，不变更身份、角色与数据权限。空状态分类为同步纯函数；图表示例沿用现有请求生命周期。新增后台不要求手机适配；历史已存在的用户移动功能与底层生成路径不在本轮删除。

## 影响、回滚与验收
稳定 V1 引擎不变。后台空状态变化随新浏览器包被应用采用；文档、Skill、模板约定来自同一权威来源并同步。可回滚本次源码/文档提交；无迁移和业务数据回滚。平台目录入口修复在服务端独立提交。
验证有模型无菜单、有菜单无权限、只有自定义报表、菜单顺序和读取授权；检查未知路径文案；运行 verify:affected、资料同步校验和 Skill 检查。Demo 复用现有 2.10.0 后台扩展接口在测试环境完成仅 PC 的真实角色导航、离开保护及报表验收，不将源码检查冒充包发布或生产上线。

2026-09-11 发布候选验证发现平台维护者浏览器 fixture 的两个旧断言仍要求“没有声明数据资源”，与本决策冲突；改为验证 `data-admin-empty-reason=not-configured` 的真实状态。权限恢复测试先等资源表就绪，并将其动态导入的客户端模块加入 Vite 预扫描入口，避免首次依赖优化重载中断测试上下文。不修改运行时代码、权限语义或重试断言，以原候选真实安装的浏览器回归验证。
