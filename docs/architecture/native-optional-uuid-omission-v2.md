# Native Optional UUID Omission V2

## Decision

A declared Native `uuid` field is business data, not platform identity. The
resource system field `id` remains generated by the platform; every other UUID
is stored only when the caller supplies it. Omitting a nullable UUID therefore
stores `NULL`, and a required UUID must be supplied explicitly.

## Public contract

- `required: true` / `nullable: false` owns logical create/update validation;
  authored UUID columns remain physically nullable.
- A field has no implicit default merely because its physical type is UUID.
- Single and transaction create have identical omission semantics.
- Adding or making a UUID required never backfills historical rows and does not
  block publication; current writes must satisfy the active logical contract.

## Acceptance

The platform physical plan contains no default or `NOT NULL` for declared UUID
fields, while the system row `id` still generates a UUID. A real PostgreSQL
create proves an omitted optional UUID is `NULL`, a current required create is
rejected when omitted, and an explicit UUID round-trips unchanged.
