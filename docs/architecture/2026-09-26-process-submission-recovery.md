# 提交响应未知时保留原操作

标准发起页在请求超时后修改字段会生成新键；现有流程回执只支持已知 commandId。新增平台只读原键解析协议，SDK 与页面复用现有流程命令和回执，不另造执行状态。

页面在发送前将原操作定位信息写入当前标签页 sessionStorage（应用、环境、用户、流程组成隔离键，值仅有操作码、幂等键、发起时间）。不保存表单内容、token 或授权快照。定位信息不授予任何权限，恢复仍由服务端重新授权。成功后删除；没有查到回执仍是未知，不能自动换键。刷新后继续查询原操作；存储被浏览器禁用时明确说明仅本页恢复，不虚假承诺刷新恢复。

发送前的表单构造错误不产生待恢复状态；标准平台提交的明确非冲突 4xx 拒绝可以修正后再提交。超时、连接断开、5xx、409、解析异常以及应用 Named Action 响应异常均保留原操作，页面提供只读查询。Named Action 未产生流程时，不能用流程未观测证明业务未写入；保留原键并报告给应用诊断，不自动执行第二次业务请求。

不自动重试写入，不把持久回执等同于审批完成。回执跨应用/环境/操作/流程/键不一致则拒绝。旧平台缺少恢复能力时明确提示，保留定位信息。查询与回退不改业务数据。

验证：响应丢失、刷新、修改输入、权限失效、错上下文响应、未观测、明确拒绝、已提交恢复；真实数据库验证归平台服务端。浏览器组件 PC/mobile 共用该恢复入口。

仅同一页面、应用版本/Head/身份作用域未变化、标准提交且已查询未观测时，允许显式重发内存中冻结的原始输入与原键。后续重试的 4xx 不能证明之前未知请求未提交，仍保持恢复；刷新后没有原始输入，不自动重构或重发。
