# 显式 TEST 维护替换消费契约

能力所有者为平台 DeploymentRun、Native Head 与 Runtime，设计依据为服务器同日维护替换 ADR。CLI/MCP 的 strategy 仅接受 rolling 或 maintenance-replace；默认 rolling，生产不能传策略。maintenance-replace 是明确停机请求，必须先通过能力发现和只读计划，不能因配额不足自动选择。

同一包可用于两种发布策略，策略属于运行请求而不改变不可变包。默认幂等键为滚动保留原格式，维护模式附加策略；显式相同键改换策略由平台拒绝。计划返回停机事实、前驱版本及 Head revision、停止后的估算容量；计划不保留资源、不执行停止。实际部署仍由平台核验和恢复。

本地校验响应必须匹配请求策略，maintenance 新候选缺少维护计划或服务端未声明策略时失败。原运行恢复只返回已绑定的运行状态，不能捏造容量保证。CLI/MCP/Skill/文档同源，同组 Changeset 可独立回退消费端；已有恢复中运行需要保留服务器恢复器。仅 TEST 显式路径受影响，1.x 和默认滚动及生产晋级不改变。

验收包含参数传递、生产拒绝、能力缺失、策略绑定、dry-run 无写、服务端失败恢复与真实数据库并发占用。发布与真实业务验收另行记录。
