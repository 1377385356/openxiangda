# 资源绑定 SDK（合同复盘 B1）

## 证据与所有者

编译器已经生成 Record/CreateInput/UpdateInput，但 Nest Data API 仍接受任意资源字符串和独立泛型；合同开发出现引用裸字符串、把信封当记录、读取错误 revision 等错误。编译器拥有字段类型，现有平台客户端拥有调用身份与传输；本变更只连接二者。

## 决策与不变量

- 生成 `ResourceTypes` 映射，用资源 code 唯一绑定记录、创建、更新类型。
- Nest 三种已有数据主体均可 `resources<ResourceTypes>()('code')`；包装只调用该服务的现有方法，每次继续核验原请求上下文。不能转成应用主体、缓存授权或新增数据存储。
- get/create/update/delete 继续返回 `data` 信封，query 保留分页。绑定层校验返回资源，拒绝跨资源混淆。记录只有 id/revision 保证必有，其余字段允许因读取权限隐藏；生成写入类型仍排除系统字段。
- query 的字段和排序键绑定到资源，select 不许伪造完整读取。更新要求显式 expectedRevision，绝不自动重读并覆盖并发变更。
- 幂等内容冲突不等于已成功，文档不得教应用把任意冲突转换为成功。

## 边界与回退

不改变平台 API、请求/响应 schema、配置 bundle 或编译协议版本；无额外网络调用、重试、权限或缓存。旧方法保持可用；1.x 无变更。回退工具包即可，不回退服务端数据。

## 验证

编译真实生成资源类型并用正反 TS 示例检查错误资源名、引用、信封 revision、系统字段、query 字段；运行调用验证同一资源名/授权/透视传递、失效上下文拒绝和跨资源响应拒绝。影响范围验证使用 verify:affected，正式包验证复用冻结候选。
