# HTTP 浏览器 SHA-256 兼容修复

状态：实施；客户稳定组合兼容发行。日期：2026-10-08。

## 证据与归属

客户内网以 HTTP 提供应用。浏览器在非安全上下文不提供 Web Crypto SubtleCrypto；标准审批在 `workflowCommandTokenDigest` 直接访问 `crypto.subtle.digest`，尚未发出审批请求即失败。`SignatureField` 对 PNG 摘要有同一缺陷。通用浏览器 SDK 拥有摘要实现；平台继续唯一拥有授权、审批状态和操作结果，应用不提供特例或猴子补丁。

## 决定与不变量

增加内部 SHA-256 字节摘要函数。有 SubtleCrypto 时继续使用它；缺少时使用固定版本、浏览器兼容的 `@noble/hashes` SHA-256。两个消费者共用实现，UTF-8 编码和小写 64 位十六进制输出保持一致。可用原生实现的实际错误继续传播，不将未知错误掩盖为兼容降级。

审批定位器仍只保存原操作号、任务、命令、时间及 token 摘要；不保存原 token、输入、权限或新的恢复状态。签名仍摘要实际 PNG 字节，包括相同文件引用和既有字段结构。无服务端协议、编译器摘要、数据迁移、权限或环境变更；V1 不消费 V2 浏览器实现。所有 HTTP V2 应用可复用。

## 失败、并发与资源边界

哈希为无状态纯计算，不引入请求、持久化、重试或共享可变状态；摘要失败仍阻止原命令发送。沿用既有 token 和签名画布输入边界，计算线性时间及固定哈希状态。只在原生路径为 BufferSource 复制输入；无 worker、定时器或后台任务。使用成熟实现，不降低为非密码哈希；HTTP 传输安全不由此功能重新定义。

## 发布与回退

当前客户为 SDK 2.59.2 / contracts 2.70.0，而主线含未发布新契约。兼容候选须保留客户精确契约组合，并与主线合入同一修复。公开 npm 版本不可覆盖；写入前可取消候选，写入后按原制品前向恢复。应用可回退到原成功 DeploymentRun；回退也会重新暴露 HTTP 摘要缺陷。新契约功能的完整发行不属于本修复。

沿用平台主仓 `2026-10-08-verified-provider-browser-login.md` 已记录的稳定组合冻结边界：先提交通用修复到 master，再以已发行 SDK 2.59.2 的源树和本主题精确文件构造可追溯的兼容候选。候选仍为 master 上的后继提交，不改写或丢弃开发历史、不创建工作树或维护分支。Changesets 的 `http` 预发行通道确定新版本，保留 npm latest/stable-v2；只发本主题候选，不发新共享契约。主线未发布内容在已推送实现提交中完整保留，正式发行后恢复该树并保留修复与发行记录。冻结期间只允许本任务写 SDK。

源码发布回执保留精确候选提交和制品，根仓先记录正式 gitlink，再恢复当前开发组合；客户只安装兼容版本，平台能力按 API 实时结果配对。若发行门禁发现已发行包内容变化，必须查明并修复，不覆盖版本或跳过不可变检查。

## 可证伪验证

- 真正缺少 crypto 或 subtle 时，空串、ASCII、中文及多块输入与独立 Node SHA-256 相同。
- 原生和 fallback 对具有字节偏移的二进制数据一致；原生错误原样传播。
- HTTP 模拟下审批定位器可成功写入，且不包含原 token 或表单。
- 标准审批在实际非安全 HTTP 浏览器中发送原审批请求并呈现平台结果；不重放未知审批。
- 发布验证消费一次冻结的 tarball；应用部署与真实业务验收分开记录。
