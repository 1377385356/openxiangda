# Anonymous public named-query batch client

The platform owns the new read-only POST anonymous-public/public/query-batch endpoint. The SDK exposes it through createAnonymousPublicClient.queryBatch without exposing ordinary anonymous Data API access. One explicit route/application/environment contains up to ten independently keyed policy/query requests, at most 500 requested rows and 64 KiB; the server executes at most three concurrently through the original immutable policy, fields, fixed filters, browser identity, query validation, rate limiting and RLS. No query expression, projection, role, SQL, authority cache or business mutation is added. Existing single-query/1.x APIs remain unchanged.

Each receipt must match key/policy/query exactly and contain either a discriminated record/aggregate result or an explicit sanitized error. Missing/duplicate/mismatched/oversized/malformed receipts fail the read; per-item 403/404/429/503 is never an empty array or zero. The client does not replay, fall back to another API, merge writes, or claim a batch is one database snapshot. Failed transports retain normal platform errors. Rollback removes callers before reverting the platform; no data repair is required.

The existing query return type incorrectly labels Native aggregate rows as record wrappers. Define explicit record and aggregate variants, retain the older value-only count variant, and export the types alongside the factory. The SDK validates batch receipts at the transport boundary. Test real request bytes, route/environment scope, discriminants, exact receipt matching, partial errors, malformed data and HTTP failure; application/browser and school performance remain separate from package verification.

Public package changes require a reviewed Changeset and frozen official release. A prior mainline 2.74.1 release is materialized but its npm version was not yet visible during investigation; do not interleave registry writes with an unfinished release, and never install a patched node_modules copy in the application.
