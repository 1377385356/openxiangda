# 持久排队命令的工具链契约

状态：实施中。对应平台根仓库 `docs/architecture/2026-09-29-durable-queued-application-commands.md` 的已确认架构。

当前 permit 模式在数据库受理前依赖浏览器，关闭页面会中断后续业务。新增显式 durable 模式，数据库受理、调度、结果与重放均由平台拥有；应用只准备只读事务计划。原 permit 默认值、配额所有权和普通事务语义保持兼容。

工具链拥有声明校验、独立能力声明、生成的 handler 清单、浏览器恢复和 Nest 执行边界。平台拥有数据库 acceptedAt、执行证明、租约 generation、限流预算与最终原子事务。应用不获得执行证明、SQL、任意 URL、后台身份或独立队列。

声明区分 intake 和 execution admission；参数最多 8 项、编码最多 8 KiB，字符串有界。计划最多 99 操作、20 守卫、64 KiB，只允许声明资源字段上的 create/update/increment。队列专用 command-accepted-at 断言不扩展普通 database-now。清单从 concurrency 推导，不新增第二份权威。

Nest handler 强制 request scope，验证网关和在线执行证明后才在私有 ALS 内解析依赖。专用证明仅可读取声明资源和发起人目录；普通 SDK 写入、事务、通知和 OAuth 在该上下文内拒绝。平台仍独立验证每次读取与最终计划，SDK 不是 Node 沙箱。

浏览器挂载只恢复和查询本人受理单；显式点击才 enqueue。未知响应保留原 key，关闭页面不取消，终态停止轮询；跨设备 mine 恢复不将历史成功当永久业务资格，管理员取消后可显式新申请。遵守服务器间隔并加入退避与抖动。

失败时不猜测报名成功。旧版不消费 durable 命令；停新受理并排空原请求才回滚。独立 capability 阻止旧平台接受新包。验收覆盖编译器一致性、权限与字段范围、错误响应恢复、跨设备恢复、重复提交与重新申请、请求构造副作用、计划引用和预算上限。发布前需平台真实关闭浏览器恢复、原子提交与分级并发实测；工具测试不证明 3000 人容量。
