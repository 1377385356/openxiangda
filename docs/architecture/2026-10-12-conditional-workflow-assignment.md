# 按条件选择审批人：共享规则与启用门禁

状态：设计已确认，分阶段实施；尚未向流程注册、画布或运行时开放。

## 问题证据与所有者

当前人员编辑器只支持直接指定成员、角色及精确复用已发布来源，不能表达金额等变量决定办理人的规则。2026-10-12 原设计会话确认使用有序 `cases` 加必填 `otherwise` 的组合来源，而不是在 UI 模拟分支或替换已有环境人员路由策略。

共享 contracts 拥有纯类型、结构/事实校验、叶子遍历与表达式求值。平台现有 Assignment 服务唯一拥有人员解析，现有 node-configuration 服务唯一拥有已发布节点的配置覆盖。SDK 只拥有编辑呈现。目录、角色、环境和任务状态不增加第二个存储或所有者。

## 不变量与契约

- 最多 20 条规则，不嵌套，总 JSON UTF-8 字节不超过 16 KiB。先命中先采用；只解析命中叶子一次。空解析使用已有空人员策略，不继续尝试后续规则。
- 条件只引用声明输入及所有入路已产生的步骤输出，不使用当前节点表单或“上一位操作者”。第一阶段可选事实仅用于 `exists(path)`；不得用可选事实做比较，即便外层存在性判断已保护。
- 条件缺失必需值、类型不符或求值异常时阻止节点进入。保留原表达式默认求值行为，严格模式为显式 opt-in，不能更改既有条件分支语义。
- 允许标准成员/角色/范围角色；主管链、字段成员、输入成员、申请人、上一节点操作者、业务关系仅精确复用已发布声明。暂不开放 `initiator_select`、`application_provider`、旧单层主管、嵌套组合。抄送与自动跳过空人不开放组合。
- 各叶子在保存/发布时都校验，包括未选中的叶子。真实角色、成员启用状态、队列/范围、所有固定版本兼容性由平台验证，纯规则成功不能代替它们。
- 任一可选连续主管链要求 sequence；还须复用主管链的组织上下文与事实检查。

## 已发布配置、快照与协商

首次发布前默认规则进入 canonical binding；发布后整项覆盖通过已有配置 revision/CAS，不能同时写草稿绑定。覆盖叶子的权限上限来自平台可编辑标准来源、节点冻结默认中的精确叶子、当前 AppVersion 的精确已发布来源。新 head 若不兼容已有覆盖，阻止激活，不悄悄丢弃。

开放任务 E 快照不变；后续进入与退回重入重新选择。快照保留命中叶子的 provider，新增 via 记录规则摘要、规则序号/默认、条件事实摘要、默认/覆盖及覆盖 revision。inputHash 包含规则、命中和叶子摘要。命中叶子继续经过现有 routing-policy 替换/追加逻辑，两种信息均记入快照。

正式开放必须同时具备 capability 协商、编译/注册拒绝旧平台、目录能力过滤、源同步整项往返、覆盖导出隐私处理以及所有嵌套叶子的角色/能力/启动预检遍历。不能先扩展 provider allow-list 再补校验。

## 当前实施阶段与失败边界

第一阶段只交付可独立测试的共享基础：独立组合类型与 Schema、严格求值、按节点事实可用性、来源权限上限、叶子遍历。不扩展既有 WorkflowBindingProvider，不调用目录、不创建任务，不让尚未集成完整的规则进入真实流程。这不是已完成的审批人编辑/执行闭环。

下一阶段接入平台 resolver/planner/配置覆盖、source sync/capability，最后接入 PC 编辑器。每阶段沿用上述同一架构，不另外建立人员预计算服务。

## 并发、安全、资源与回退

覆盖沿用整项 CAS/锁，不做逐规则合并。禁止危险属性路径、非 JSON/循环值、超长路径、无限 AST、无限图遍历；只有已选叶子在进入时触达目录或后端。纯基础模块无写入、副作用与数据库迁移，对未启用的 V2 与稳定 V1 不产生语义变化。启用前可回退此阶段源提交；启用后不得在仍有该能力版本的环境直接降级旧运行时。

## 可证伪验收

共享层：有序首命中/默认、错误不默认、短路未读取事实、exists 可选事实、严格类型且旧语义不变、每条叶子/兜底全量检查、限制与未知字段、步骤输出全入路、权限三集合与连续主管约束、ESM/CJS/browser 同源构建。

平台/界面阶段另验：只调用选中人员解析一次、空人不回落、真实成员/角色范围、覆盖 CAS、开放 E 不变/下次进入采用新规则、新 head 不兼容被阻止、旧平台拒绝、源同步摘要往返、PC 编辑及真实保存→发布→任务→角色→业务读回。基础层测试不证明这些后续阶段通过；本轮无 npm 或生产发布授权。
