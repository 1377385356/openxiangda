# 开发者资料与执行流程统一

状态：用户已要求实施，2026-09-06。整体设计位于平台根仓库的 `docs/architecture/openxiangda-v2-developer-experience-design.md`。

## 证据与所有者

当前 MCP check 没有传入环境，跳过 CLI 默认执行的兼容性预检；文档索引不能读取正文，Skill 和 AGENTS 使用重复英文规则。开始开发、字段、查询、发包责任方等说明与当前代码冲突。统一的开发者用例归 Devkit，CLI/MCP 只适配输入输出；中文使用专题归工具链文档，根包分发同一内容，Skill 负责按任务选择资料。

## 不变量与契约

- 当前登录用户、角色并集、数据权限与部署状态仍由平台拥有。普通 CRUD 与标准审批不启用应用后端。
- 用户侧环境名使用 test/production，由共享适配层映射平台 preproduction/production；生产发布必须复用成功测试运行。
- 用户侧 check 默认先做本地完整配置校验和目标兼容性预检；显式 `check --local` 用于候选包、CI 或离线验证，结果标明未验证目标平台。正式 deploy 始终执行目标预检。检查会写本地结果，不能声明只读。依赖阶段失败后停止后续构建。
- 文档只按发布清单中的稳定主题读取，限制大小和章节；禁止任意文件路径或远程抓取。根包和 Skill 都由同一中文源文件构建。
- 生成 AGENTS 的平台段可更新，用户段完整保留；没有已识别平台段的旧文件不自动删除。
- 改动仅影响独立 2.0 工具链，不修改 1.x、租户业务数据、平台数据库和生产部署。

## 失败、并发、资源和回滚

工具错误保留结构化错误码、指针和下一步。只读发现不运行检查/构建或创建远端对象。已有部署恢复以平台回读为准。本地写入和发包进程必须互斥，锁只代表本地进程，不代表部署状态；不确定锁不得自动抢占。新增资料入口出现缺失、摘要不符或无效选择器时显式失败。

开发者中文资料与共用执行用例作为一个可独立验证的提交，发布互斥另作独立提交，使用 Changeset 记录发行包影响。尚未发包时可回退相应源码提交；发行后用后续版本修正，不覆盖已发布版本。生产晋级不会从本地重新构建。

## 验证

通过真实 MCP 内存传输验证检查目标、生产输入约束、错误与文档资源；CLI 使用同一用例并运行黑盒测试。用临时目录验证文档路径限制、Skill 安装、AGENTS 保留、检查失败不构建，以及两个发布进程互斥。执行受影响包验证、文档构建及实际 tarball 分发检查；不把这些结果描述为真实站点业务验收或 npm 发布。
