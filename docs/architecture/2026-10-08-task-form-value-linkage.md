# 审批补填页面的受限值联动

状态：实施。授权来源：当前会话持续授权平台修复及全部本地流程迁移测试。

问题证据：B20四流程集中验证发现，提交页已有valueLinkage，正式审批页没有对应入口。
源YWTB-010秘书在会议日期、公示日期和地点变化时生成意见；手填不能代替源自动联动。

能力所有者：应用提供按workflowCode选择的同步纯函数，平台TaskForm负责规范字段编码、
当前可编辑字段筛选、未保存输入、草稿和原命令恢复。Kernel继续唯一拥有授权、CAS、
任务完成、拓扑、字段写入与流转事实。不创建新接口或第二回执存储。

不变量：联动只响应用户修改，不在加载、重读、草稿恢复时覆盖已有输入；输入仅含
当前可见可编辑字段，输出只能写同一集合的普通字段。当前批次不允许联动对子表、
附件或系统字段编程写入。全patch先检查后应用；抛错/异步/越界均不部分更新，
保留用户修改并阻塞提交至规则恢复。锁定、CAS冲突与未确认原操作时不运行。

契约：OpenXiangdaApplication.workflowTaskForms[workflowCode].valueLinkage；回调额外接收
workflowCode/nodeId/pageCode。未配置应用与1.x无行为变化。无后端/权限/生产配置更改。

容量：一个用户变化运行一次同步回调；字段集合有界于已获授权TaskPage，递归输入复制
沿用提交页规则。不能通过回调发起请求、创建任务或选择新操作所有者。

回滚：移除应用注册即可恢复人工填写；新增SDK属性可独立移除，不改变持久数据。

可证伪验收：日期规范编码、手工意见保留、清空保留原意见、受保护/隐藏/子表/异步
patch整体拒绝、原CAS与正常任务命令不变；PC和390px秘书原任务实际自动生成并办理。
源码联调验证后统一冻结一次SDK，不发布npm，不修改学校生产或发送学校消息。
