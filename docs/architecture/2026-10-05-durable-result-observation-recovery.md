# Durable 原结果观察的短读取恢复

## 问题与能力所有者

万人冷入口实验中，86 个已经受理的原命令在客户端收到 `CONCURRENCY_READ_RECOVERY_EXHAUSTED` 后结束观察，数据库随后仍全部终结。客户端将一次两分钟读取预算耗尽当成整个三十分钟观察结束。SDK durable 控制器拥有原命令观察；平台 PostgreSQL 仍拥有命令与最终事实。

## 设计与不变量

只在已经确认 scoped 回执后的自动原结果轮询中，允许 SDK 自身明确标记 `status=504`、`retryable=true` 的 `CONCURRENCY_READ_RECOVERY_EXHAUSTED` 进入延迟只读恢复。不得把它误称为服务端忙，也不修改通用读取分类器。仍沿用原 operationId、requestKey、firstSubmittedAt、两分钟单次读取预算、服务端建议间隔和三十分钟绝对截止时间。

权限、依赖不可用、普通网络错误、未知 504、不可重试错误保持停止；未确认受理的 intake/discovery 不自动获得此策略。离页、身份变化、停止和新观察 generation 均停止旧读取。自动恢复不调用 enqueue，不续期、不修改票证或名额。

## 资源、发布与回滚

使用既有指数退避（最长基础间隔两分钟）与抖动，不增加并行请求。单次读取和总观察均有界。公开方法及服务端协议不变；使用正式 SDK patch 发布并精确依赖，不修改已安装 dist。回滚为前一 SDK 包；数据库事实不受影响。

## 可证伪验收

- 短读取耗尽后仍在原三十分钟预算内读到原命令终态，只有一次 enqueue。
- 连续耗尽最终以原观察截止结束，没有续期、补写或无界循环。
- 错误码、状态或 retryable 不匹配时停止；403、依赖 503 和普通网络错误不被恢复掩盖。
- 停止或观察被替代时，旧请求不能再读或更新快照。
- 单元验证与真实客户容量测量分别记录，失败实验不追认通过。
