# Handling nodes

Approved basis: Claude P1 execution contract of 2026-10-11. The existing workflow kernel, canonical compiler, task ownership, assignment resolution, field contract and notification hub remain authoritative.

Add canonical kind handle with next and complete. Complete is a mandatory stable forward action; the handler dispatch remains absent for this new command. It records completed outcome and task.completed rather than approval, with the existing internal seat completion state. Single/any/all/sequence retain human task completion rules. Save writes shared data without completion. Return/transfer/delegate reuse current authority; reject, add-assignee, automatic approval, completion deadline and skip-empty are prohibited on handling nodes.

Entered policy/pages/people remain pinned and outgoing next uses current routing. Canvas insertion requires a released handle template and its code-owned field policy, action minima and task page. The canvas and assistant use the same validator.

Writes keep task/request locks, current token, idempotency receipts, CAS and existing tenant/environment authorization. Configuration bounds and concurrency limits do not widen. No second state store or automatic effect execution is added. V1 is unaffected. New canonical kinds require coordinated SDK/server deployment; application capability negotiation prevents use against old servers. Existing approval definitions remain compatible. Source rollback must retain support while handle requests exist.

Verification: full canonical compilation, planner blocking on a handle, complete-only policy, meaningful completion audit, rejection denial, required fields versus shared Save, all-mode completion, routing after adoption, released-template denial, and browser action/canvas labels. Source tests and live role acceptance are recorded separately.
