# 应用自定义后台外观与平台导航事实

状态：实施中。2026-09-29 用户明确要求允许应用自定义后台层、导航与扩展；该决定替代旧文档中“不得替换平台 Shell 外观”的限制。

## 证据与能力所有者

应用为了实现既定设计需要用 CSS 隐藏 `.oxa-sider`/`.oxa-topbar`，但生成 CRUD 页面无法统一覆盖，应用还容易复制菜单和角色判断。React runtime 已拥有路由、身份、权限过滤后的导航和退出登录，外观应允许应用决定。

## 决定与不变量

通过 `OpenXiangdaApplication.ui.admin` 提供完整 `shell` 以及 `header`、`sidebar`、`footer` 插槽。所有插槽接收同一平台生成的模型：权限过滤后的菜单、中心入口、当前页、选中路径、登录人、角色名、视角与导航/退出命令。应用只提供 React 展示，不新增 Router、身份缓存、角色快照或授权服务。

`centerNavigation.workflow` 与 `centerNavigation.messages` 仅控制后台导航显示，不能撤销工作流能力、删除深链接或扩大权限。默认均显示；应用隐藏时负责在自己的业务入口提供审批可达性。

默认无扩展的应用保持现有布局。配置扩展后，同一自定义壳层覆盖后台自定义页面和标准资源的列表、创建、详情、编辑及移动路径；用户端和登录页不受影响。后台访问守卫在壳层外执行，隐藏菜单不视为授权。默认插槽作为 React 节点提供，允许局部定制。

## 失败、并发、安全与资源

所有状态仍来自既有 RuntimeBoundary、ApplicationRouter 和标准资源组件。壳层故障由局部错误边界显示重试及返回应用入口，不吞掉业务提交，不重放写入；退出使用原接口与原导航守卫。导航模型只包含有权页面，身份切换/权限更新由平台运行时重算，不保留旧用户的菜单快照。无新增网络请求、数据库变更或业务数据写入。

## 影响与回滚

仅 V2 React UI 包和开发资料，V1 引擎不变。撤销 `ui.admin` 即恢复默认外观；可独立回退 SDK。应用不能通过插槽改变服务端权限或记录范围。

## 可证伪验收

- 默认 Shell 的导航、退出、视角及表单抽屉保持现有行为。
- 自定义 Shell 同时接管生成列表和深链表单，且没有重复平台顶栏。
- 普通用户不能通过自定义 Shell 进入管理路由；菜单仅包含授权页面，多角色仍取并集。
- 单独隐藏消息/待办导航不删除原路由；深链权限保持原结果。
- 插槽异常有可操作错误页；切换路由可以恢复，不触发重复业务请求。
- PC/移动及键盘操作通过真实浏览器 fixture；构建、单元测试与浏览器证据分别记录。
