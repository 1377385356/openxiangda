# Agent 原生视觉设计与实现闭环

状态：2026-09-17 用户明确确认实施。本决定取代
[OpenDesign 设计能力接入](./2026-09-11-opendesign-capabilities.md)和
[OpenDesign 原生运行时与 CLI](./2026-09-11-opendesign-native-runtime.md)的当前默认路径。

## 问题证据与决定

OpenDesign 被接入为所有界面任务的强制前置步骤，但实际应用仍由 AI Agent 在
OpenXiangda 工作区内实现和验收。当前链路额外引入桌面安装发现、CLI 身份探测、
daemon/MCP、独立项目、导出和 AppSpec 搬运，却没有稳定提高最终页面质量；没有人工
设计师参与时，独立设计运行时还会把低质量中间产物固化为实现约束。用户实际使用后
明确认为效果不理想，并要求由 Codex 直接使用 Image 2.5 生成设计参考后完成开发。

OpenXiangda 2.0 删除 OpenDesign 原生运行时桥接、`openxiangda design` 命令和专属
分发资料。界面任务改为 Agent 原生闭环：先从 AppSpec、平台契约和真实任务确定页面
与状态，按需使用当前 Agent 可用的图片生成能力（包括用户指定的 Image 2.5）形成少量
视觉参考，然后直接实现真实 React 页面，在浏览器中按目标尺寸、交互和角色反复检查。
图片是可选参考，不是应用结构、交互、权限或验收的权威事实。

## 能力所有者与稳定不变量

- 当前 AI Agent 是视觉方向、实现迭代和浏览器修正的唯一执行者；不建立第二个设计
  Agent、项目状态库或外部设计运行时。图片模型只返回视觉输入，不拥有设计状态。
- AppSpec 继续拥有产品决定、逐页交互、视觉范围、确认和验收记录；`appspec/design`
  继续固定本轮采用的参考图、设计说明、token 和必要原型，并沿用资源摘要和失效规则。
- 可运行 React 页面是最终界面事实。加载、空、失败、拒绝、校验、提交中、成功、
  未保存输入、键盘和响应式行为必须在真实组件与浏览器中验证，不能从静态图片推断。
- 平台继续唯一拥有 Shell 路由、当前用户、授权菜单、业务数据、权限与部署状态。
  标准后台、Field Kit、PC/移动组件和 Data API 边界不因视觉流程变化而改变。
- 管理后台仍是默认应用骨架；用户端 PC/移动端按真实旅程设计。不得用图片、单页
  HTML、iframe、独立假后台或本地模拟权限替代平台入口和业务验收。

## 受影响契约与兼容性

- 删除 `openxiangda design open|status|cli`、OpenDesign 环境变量和原生参数透传。
  调用旧命令会进入统一的 `OPENXIANGDA_COMMAND_NOT_FOUND` 边界，这是本次明确批准的
  预发布破坏性删除，不保留兼容别名或静默回退。
- `design-workflow` 保留为工具无关的 Agent 视觉开发专题；删除
  `opendesign-methods`、`design-craft` 主题和随包上游快照。Skill、模板 AGENTS、CLI/MCP
  资料目录与打包测试同步更新。
- `openxiangda.appspec/design/v1`、设计确认、资源摘要、主题输入和
  `OpenXiangdaApplication.ui` 保持兼容。既有 `appspec/design` 文件仍可读取和校验；
  不要求迁移或删除历史 OpenDesign 来源记录。
- 本轮只影响 V2 本地工具、资料和发布包；不修改平台后端、数据库、远端应用、V1
  引擎或任何租户数据。稳定 1.x 应用和已部署 V2 应用运行时不受影响。

## 失败、并发、安全与资源边界

图片生成不可用、失败或结果不合格时，Agent 记录事实并直接使用产品约束、设计 token、
成熟组件和浏览器迭代继续开发；不得伪造图片或通过结果。静态设计稿不得阻塞权限、
表单和关键业务状态的实现，也不得被当作业务验收证据。

同一应用工作区仍保持一个写者。参考图只保存任务实际采用的少量本地文件，继续受
AppSpec 的路径、文件数、单文件大小、总大小、目录深度和符号链接限制；不为了设计
流程下载不受信任的远程代码、执行图片内容、泄露业务数据或绕过素材授权。外部品牌、
人物和业务素材只有在用户提供或明确授权时使用。

## 回滚边界

本变更作为一个独立发布单元回滚。回滚对应提交可恢复 OpenDesign 命令、资料和测试；
不会修改或删除用户机器上已有的 OpenDesign 安装与项目。新流程产生的通用
`appspec/design` 参考图、token 和实现代码不依赖新运行时，回滚工具链也不会自动改写。

## 可证伪验收

1. CLI 注册表、源码命令目录、根分发帮助和候选 tarball 均不再暴露 `design`；执行该
   命令返回统一 command-not-found，且普通 `--cwd` 仍由分发器正确解析。
2. 当前资料目录只保留新的 `design-workflow`；MCP、Skill 安装、模板 AGENTS 和打包
   产物不再引用 OpenDesign、其安装、CLI、MCP、daemon、方法或 Craft。
3. AppSpec 设计资源摘要、确认失效、大小和路径边界测试继续通过，既有设计资源无需
   OpenDesign 即可检查。
4. 设计工作台继续在真实 PC/移动组件上通过浏览器场景，包括空、失败、拒绝、校验、
   提交恢复、未保存输入、响应式和主题作用域；截图不能替代这些断言。
5. `pnpm verify:affected`、Skill/资料同步检查和候选包 smoke 对本次受影响范围通过。

## 未采用方案

- 不把 OpenDesign 留作核心中的可选命令：这仍需长期维护安装发现、上游接口、测试和
  文档，并继续让用户误以为它是受支持的默认路径。将来若质量和需求成立，应作为独立
  外部 Skill 或插件重新评估，而不是恢复隐式核心依赖。
- 不采用“只生成一张图片后照图实现”：静态图无法定义授权、字段协议、交互状态和
  响应式行为。图片只帮助选择视觉方向，真实代码和浏览器证据完成设计闭环。
