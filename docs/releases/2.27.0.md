# OpenXiangda 2.27.0：精确额度审批生命周期

补齐主子记录精确金额占用的审批终态声明、原轮次事务参数及撤回修订重提接入，保持平台对金额、身份和审批事实的统一校验。

## 新增能力

- HTTP 事件订阅可声明同资源审批的额度终态：通过继续占额，驳回或撤回释放；两侧编译器共同校验审批、资源、状态和固定迁移模式。
- Native 事务支持绑定原 reservationKey、transitionKey 和唯一子记录 update，Nest 继承已验证的事件上下文，不允许客户端自报额度迁移模式。
- 提供本人 FormDraft 与 BusinessProcess update 重提组合示例，将修改正式金额、重新占额、消费草稿和生成审批命令放在同一平台事务。

## 修复问题

- 事件终态声明参与能力使用摘要；目标必须满足 data.decimal-reservations@1.1.0，不能把仅有数据表和通用防护的旧服务端当作完整额度能力。

## 受影响用户

- 需要以主记录金额约束多条子记录，并在审批通过、驳回、撤回和重提间管理额度的 OpenXiangda 2.0 应用。

## 升级步骤

- 应用固定 openxiangda@2.27.0，更新锁文件，重新生成契约并执行适用检查；平台同步升级匹配的公共编译器、额度实现和向前迁移。
- 在实际资源和审批中声明 reserve 动作及终态订阅，先确认没有未入账的历史子记录。保留未完成请求的原幂等键和输入。
- 预发验证并发超额、精确小数、权限拒绝、通过保留占额、释放一次及同记录修订重提。真实验收前保持额度入口禁用。

## 已知限制

- 普通 CRUD 不开放 released 子记录保护字段写入；修订先保存本人草稿，再通过原子 update 重提。
- 作废或终止需要另行实现真实受管业务动作，签后金额变更不在首批能力内。旧轮次事件不能释放新轮次额度。
- 原回执重放仍要求当前授权、有效事件租约和父记录可读性。
- 公开包发行不是客户部署或业务验收，不提供应用侧浮点求和替代台账的降级路径。

## 关联 Issue

无。

## 兼容要求

- node: >=24
- workspaceGenerations: v2
- platform: 额度应用要求 data.decimal-reservations@1.1.0，并使用与目标平台一致的共享编译器。未启用额度的应用保持原有行为。
- v1: 独立 V1 引擎和工作区不受影响。
