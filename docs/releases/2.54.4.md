# 原子业务审批的最终状态合同修正

同源SDK的审批事务守卫对齐Workflow实例实际的已通过、已拒绝状态，防止最终审批或驳回被错误阻断。

## 新增能力

无。

## 修复问题

- expectedTransition.status使用running、approved、rejected、withdrawn；拒绝将任务completed状态当作实例状态。
- Schema与公开TypeScript类型同步，补充四种实际状态与错误completed状态的回归验证。

## 受影响用户

- 显式使用definition.commandHandlers及BusinessProcess.commandWithData的V2应用。

## 升级步骤

- 整体使用同源SDK发行，并配套接受实际实例状态的平台Server；在测试环境验证原token、回执、补填及业务效果的原子提交。

## 已知限制

- 这是本机测试候选，npm发布和真实三端业务验收分别记录，源码检查不代表完成交付。
- 固定handler仍仅支持approve、reject、withdraw；不降级为分离事务，也不支持跳转、强制决定或自动同意。
- 正式npm发行验证仍需配套参考应用锁文件；本机同源制品不替代该门禁。

## 关联 Issue

无。

## 兼容要求

- node: >=24
- platform: workflow.business-data-command@1.0.0，Server使用真实实例状态与同事务Native效果。
