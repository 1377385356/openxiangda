# OpenXiangda 2.34.0：持久排队业务计划与结果恢复

新增由平台持久受理并自动处理的业务命令，支持关闭页面后继续执行与本人跨设备恢复。

## 新增能力

- 新增 durable 受管命令、独立能力门禁、有界参数及生成的 backend-plan handler 清单。
- openxiangda/nest 提供受执行证明约束的只读计划 handler，平台负责最终原子提交。
- openxiangda/react 与 mobile 提供 useDurableCommand，支持显式提交、原键恢复、本人结果和退避轮询。

## 修复问题

- 严格区分内置 permit 配额所有权与应用 durable 计划，普通业务模型无需迁移到命令独占所有权。
- 执行上下文拒绝普通 SDK 写入、事务、通知和 OAuth，读取响应验证标准记录结构。

## 受影响用户

- 构建活动报名、预约、抢票及其他需要持久排队事务的 V2 应用开发者。

## 升级步骤

- 升级 openxiangda 到 2.34.0，重新安装依赖并生成应用契约。
- 先部署支持 data.managed-concurrency.durable@1.0.0 的平台，再声明 durable 命令、handler manifest 和前端恢复流程。
- 在隔离测试数据上验证关闭浏览器、原请求恢复、取消后重报和业务原子结果，再分级测量实际容量。

## 已知限制

- 应用只返回受声明约束的事务计划，不能在 handler 内发送通知或调用普通写入接口。
- 受理成功不等于业务成功；队列位置为近似投影，不能推导精确等待时间或服务器容量。
- 旧 permit 模式保留，未升级平台会拒绝 durable 包；回滚前须停止新受理并核对已有请求。
