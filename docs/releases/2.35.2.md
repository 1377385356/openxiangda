# OpenXiangda 2.35.2：运行时繁忙恢复与可读流程图

应用进入时可有界等待平台明确的繁忙响应，同身份刷新保留页面和原申请；流程图使用与不可变执行定义同源的投影展示说明、变量来源与实例路径。

## 新增能力

- 现有运行时 current 读取在明确的入口繁忙时按服务端提示和抖动退避，最长等待五分钟、最多一百二十次读取，并支持离页取消。
- 公开 WorkflowReadability、validateWorkflowReadability、projectWorkflowGraph 及共享 WorkflowDiagram，展示流程说明、条件优先级、变量来源和持久执行决定对应的路径，支持搜索、键盘及窄屏节点列表。
- 流程图使用懒加载 React Flow 与 ELK 正交布局，支持直角连线、平移缩放、节点定位、分支条件标签和缩略导航。
- 审批节点可显式声明管理员可调整的模式、人员来源和按钮上限；编译器复用有界校验，SDK 提供配置读取、CAS 更新和幂等回执，任务冻结有效配置。

## 修复问题

- 启动、焦点和可见性检查合并挂起身份读取；同身份刷新保留已验证页面和草稿，临时服务故障可重新检查，真实身份、环境、权限作用域变化或拒绝使旧受管客户端失效。
- 退出通知优先于仍在加载的身份请求，旧响应和取消回调不会恢复旧身份或覆盖登录入口。验证 current 成功后仅清除当前路径的入口等待截止。
- 安全只读传输故障最多三次总尝试；权限投影等待保留原十秒限制，普通应用请求和写入不会因本次修改自动重放。
- 管理员流程节点配置使用平台已有的 admin controller，修正上下文、配置读取和保存地址，保留环境、CAS、幂等操作标识与权限拒绝。
- 管理员流程节点配置保留平台返回的具体冲突错误码，页面可准确提示配置修订和幂等冲突。
- StrictMode 同一提交的清理、重挂载接管原 current owner，避免重复初始化读取；观察取消立即生效，无人接管时释放共享请求，安装身份必须仍有活跃观察者，原读取预算与退出优先级保留。

## 受影响用户

- 使用 V2 运行时及持久排队能力的活动报名、预约、抢票应用开发者。
- 需要展示不可变流程定义、说明及实例执行路径，或启用有界审批节点配置的平台维护者和应用开发者。

## 升级步骤

- 将应用 openxiangda 精确升级到 2.35.2；平台流程图消费者将 openxiangda-contracts 精确升级到 2.35.0，同批工具链使用 openxiangda-devkit-core 2.36.0 和 openxiangda-cli 2.6.20，更新锁文件。
- 统一验证运行时繁忙恢复、同身份刷新、退出与真实身份切换，以及流程图说明与持久执行路径后发布同一冻结候选；启用管理员节点配置时确认平台支持 workflow.node-administration。
- 在目标服务器另外测量完整页面进入、提交、自然结果查询及最终处理时间；客户端恢复测试不作为硬件并发容量证据。

## 已知限制

- 运行时繁忙恢复只用于现有 current 读取；未知 429、权限或版本拒绝和非繁忙依赖失败不扩展等待，初始化成功不表示业务请求已经受理。
- 本次发布保留持久申请的原请求键、观察截止和自然轮询策略；队列的受理、执行和最终结果仍由平台负责。
- 流程图说明不改变不可变执行定义及持久实例决定，不补造不存在的执行边，也不改变流程授权。
- 管理员节点配置只调整应用明确开放的边界，字段行为继续由应用页面与代码维护；未声明该能力的应用不启用新的配置入口。
