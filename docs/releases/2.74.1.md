# 隔离共用人员来源的节点级主管校验

修复给单个节点配置逐级主管时，错误要求其他共用同一源码绑定的节点也改变审批模式的问题。

## 新增能力

无。

## 修复问题

- 普通来源与条件规则的主管叶校验只检查当前被编辑节点，不将节点覆盖误当作共享源码绑定的全局修改。
- 保留完整原图、步骤输出及事实支配关系校验；全局源码绑定变更仍对全部真实引用执行严格主管规则。

## 受影响用户

- 多个审批或办理节点共用角色来源，并为其中一个节点选择逐级主管的OpenXiangda V2应用。

## 升级步骤

- 消费同批正式工具组合与共享contracts，更新配套平台后在TEST验证普通及条件来源、节点模式和真实角色。
- 无需修改另一节点、复制业务绑定、改历史任务或重放审批来绕过旧误报。

## 已知限制

- 本修复不配置真实组织主管，也不代表AI模型、OCR、真实角色或客户部署已验收。
- 沿用原生人员来源的已发布参数上限、组织上下文、逐级连续办理必须sequence及在途冻结边界。

## 关联 Issue

无。

## 兼容要求

- node: Node.js 24 or newer for maintained toolchain
- generation: OpenXiangda V2; V1 unchanged
- platform: Paired workflow source catalogue and node-configuration services; shared native validator must match this release
