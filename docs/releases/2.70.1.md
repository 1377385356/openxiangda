# 业务待办通知与旧审批当前节点接续

应用事务可通过签名事件创建和结束真实待办；管理员可使用正式迁移回执将旧审批接续到原当前节点，保留原申请人与审批轮次。

## 新增能力

- 事件订阅显式声明 business-task 与任务代码清单，Nest sendTaskFromEvent 投影原事件并复用平台任务中心、通知发件箱及结束状态。
- CLI 与 MCP 共享 workflows.legacy-prepare、workflows.legacy-apply、workflows.legacy-receipt 有界管理操作；旧审批历史作为来源事实保留。

## 修复问题

- 声明检查器与打包器完整保留待办任务代码清单，应用与平台编译器共同协商 notification-hub-v2.event-tasks。

## 受影响用户

- 需要预约审批、排队分配、结算确认等业务待办，或需接入有可靠来源证明的在途旧审批的 V2 应用。

## 升级步骤

- 安装精确 openxiangda 2.70.1 组合并重新生成契约；先部署同源平台 contracts、后端及旧审批接续 SQL。
- 业务状态与不可变待办事件同事务；旧审批先正式导入原业务单，再准备和执行原节点接续，未知结果查询原回执。

## 已知限制

- 本次 SDK 发行不代表目标平台或应用已部署，也不证明真实角色办理或外部供应方送达。
- 旧审批接续仅支持可靠身份、完整线性历史、手动审批和内部当前分派；不重放旧通知，不创建替代账号或伪造原申请人登录。
- 真实消息通道须沿既有发送授权启用；新增任务能力不授权批量补发历史通知。
