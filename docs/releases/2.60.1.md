# OpenXiangda 2.60.1：显式父资源读取策略

新增原生子表父资源读取策略，保持同一有效成员关系内的完整授权链；本次同时物化完整主线中已存在的六项工作流界面与查询维护。

## 新增能力

- 原生子表可声明 parentRead，由平台绑定唯一父资源与子表字段，并以同一有效成员关系同时核验子、父、范围与读取视角。
- 公开 contracts/devkit 提供同源解析器与能力协商，根包及 CLI 模板传播精确配套版本。

## 修复问题

- 收录主线已有工作流画布缩放、面板、受控选中和按钮点击/键盘命中整理。
- 收录主线已有工作中心服务端分页搜索及流程不可读取/不存在状态的中文呈现。

## 受影响用户

- 需要通过父记录权限读取 owned 子表的 V2 应用开发者，以及使用标准工作流界面和工作中心的用户。

## 升级步骤

- 按正式版本组合升级平台 SQL 与服务器，再按锁文件安装精确工具包并刷新同版本资料。
- 启用 parentRead 前核验 data.parent-read-policy 能力，保留原业务 UUID、父子外键和 Head 回执。

## 已知限制

- 仅支持只读、唯一父资源、单层 owned 子表；禁止应用自定义外键、多跳、循环及借读取扩大写权限。
- 隔离 PG15 实际 kernel 与合成授权测试不替代学校真实角色、页面、文件及性能验收。
- 本次包含完整既有 master 维护，不是只发布 G04 源码；后续 selected-department 与 managed-file 契约仍各自独立发布。

## 关联 Issue

无。

## 兼容要求

- node: >=24
- platform: 启用 parentRead 需要配套 data.parent-read-policy 与正式 SQL 迁移
- v1: V1 不消费新增 V2 parentRead 契约。
