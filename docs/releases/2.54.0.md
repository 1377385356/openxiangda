# 按资料权限受控删除关联流程

标准详情提供显式的资料删除影响预览与确认，沿同一成员的资料范围复用 Native 事务和 Workflow Kernel 的删除命令与回执。

## 新增能力

- 模型可选 recordDeletion.delete，声明自动派生 data.workflow-record-deletion@1.0.0，无需额外初始化开关。
- 同一成员须同时拥有资料 read、delete 和全部维护能力，保留原行权限，不授普通编辑或通用流程管理员权。
- 公开预览、执行、原回执 SDK 与标准详情弹层；未知结果固定原键、原因和预览，先恢复结果。
- 无关联实例沿 Native 事务，唯一关联实例沿 Kernel admin_delete；待启动、多实例及明细另有关联明确阻塞。

## 修复问题

无。

## 受影响用户

- 需要将资料维护权限与流程管理员权限分别授予的 V2 应用及平台维护者。

## 升级步骤

- 消费同源 SDK/contracts/devkit 与提供 data.workflow-record-deletion@1.0.0 的 Server。
- 显式声明 recordDeletion 与资料 read/delete、维护能力，沿同一成员的数据范围执行。
- 未知提交先核原回执；只有专用回执不存在且原预览有效时，显式用原请求重试。

## 已知限制

- 本批仅本地包，无 npm 发布；真实应用六组权限与正式本地部署验收仍待共享平台验证窗口。
- owned 删除上限100条、深度8；多个关联实例、待启动命令及明细关联其他实例不支持自动删除。
- 预览有效期五分钟，过期后仍可恢复原回执；原 CSRF 绑定保留在既有512条身份缓存中，容量淘汰、退出或刷新后不保证恢复。页面不跨刷新保存原请求。
- 合成组件及隔离数据库证据不代表103条源流程完整业务验收。

## 关联 Issue

无。

## 兼容要求

- node: >=24
- platform: data.workflow-record-deletion@1.0.0；复用既有 Native 与 Kernel 数据表及平台密钥，无新增初始化开关。未声明应用与1.x保持原行为。
