# OpenXiangda 2.17.1：用户标准面共享契约闭合修复

共享编译器接受并校验生成式用户标准面的路由契约，2.17.0 声明 user 面的应用可完整通过本地校验与部署；生成码分隔符统一为点号。

## 新增能力

- 生成码分隔符统一为点号（user.资源码.records / user.资源码.submit），与设备路由码一致。

## 修复问题

- 修复 2.17.0 中 user 声明触发 NATIVE_CODE_INVALID / NATIVE_CONTRACT_CLOSURE_MISMATCH：共享校验器按配置事实（资源存在、能力等于 read/create、码与路径形状）校验并并入用户标准路由，配置 bundle 不变，旧平台无需升级。
- 生成码统一为 user.资源码.records / user.资源码.submit，符合稳定码模式。

## 受影响用户

- 使用 openxiangda 2.17.0 并声明 user 用户面的应用开发者。

## 升级步骤

- 应用精确依赖升级到 openxiangda 2.17.1 后重新运行 check 与部署。

## 已知限制

- “我的记录”的本人过滤仍是查询层展示过滤，非服务端授权边界。

## 关联 Issue

无。

## 兼容要求

- node: >=24
- workspaceGenerations: v2
- platform: 无平台配合要求；配置与契约 bundle 对既有平台保持可部署。
- v1: 不改变 V1 运行时或应用。
