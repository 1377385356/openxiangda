# OpenXiangda 2.40.0：持久业务步骤与原结果恢复

固定版本的计算和有回执的外部业务步骤成功后再推进流程；已收结果受阻时保留原执行键并恢复后续流转。

## 新增能力

- Workflow action 声明、闭合输入输出、步骤事实来源和可读图。
- Nest 处理器使用平台持久回执；副作用每次先核对原执行键。
- 标准管理端与公开 SDK 共用受阻步骤恢复组件。

## 修复问题

- 浏览器步骤合同与 Node 签名、摘要计算分离。

## 受影响用户

- 需要计算后分支、审批间业务步骤或有回执的集成操作的 V2 应用开发者。

## 升级步骤

- 使用机器确定的同批包并冻结锁文件；本批仅本地 tgz 测试，不发布 npm。
- 平台内核及正式 SQL 同批更新，自动提供 workflow.durable-business-step@1.0.0。
- 为每个固定版本保留处理器实现、订阅和闭合 Schema；应用通过统一 openxiangda 入口使用。

## 已知限制

- 字段权限继续由页面代码维护，流程连线、代码和条件只读。
- 步骤后不支持未预备的 HTTP provider 或发起人选人；先产生有 Schema 的人员结果再使用原生解析器。
- 输入输出各 16KiB、回执 2KiB、200 节点；自动推进恢复最多 5 次、每批 20。
- 学校迁移和生产发布需要独立验收；此更新说明不代表实际运行验收完成。

## 关联 Issue

无。

## 兼容要求

- node: >=24
- workspaceGenerations: v2
- platform: 配套 Workflow 内核、252 SQL 迁移及 workflow.durable-business-step@1.0.0；无新增默认关闭开关。
- v1: 原 V1 分发与运行时保持。
