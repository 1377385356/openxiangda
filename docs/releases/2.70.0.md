# 组织角色与业务记录归属边界

应用可声明平台目录角色映射、self/subtree 组织范围及 Native 记录组织归属，由配套平台统一执行身份与数据授权。

## 新增能力

- 角色显式声明 organizationReach；directoryRoleSources 将可信平台目录事实映射为当前组织内的应用角色和班级等字符串范围。
- Native 资源声明 none、owned 或 inherited-down 组织策略；组织归属元数据可用于有界读取和统计，业务输入不能更改归属。
- 编译器共同校验组织角色、来源范围和资源策略，自动协商 authz.organizations、authz.directory-roles 与 data.organizations 能力。

## 修复问题

- 隔离 CLI 候选构建保留固定 Corepack 缓存，嵌套源码构建并发上限为两个任务；保留真实依赖安装和端到端检查。

## 受影响用户

- 使用多组织、教育局与独立学校或平台家校目录的 OpenXiangda V2 应用；已有未声明组织策略的应用保持原授权语义。

## 升级步骤

- 安装精确 openxiangda 2.70.0 官方组合并刷新项目资料，检查生成契约及能力要求。
- 平台配套正式 contracts、组织角色投影服务与新增 SQL 后再启用组织资源；在目标站点验证真实来源、活动成员、安装及角色正反路径。

## 已知限制

- npm 包发布不代表平台部署、真实组织同步或业务验收；源码和独立 PostgreSQL 测试不能代替现场登录与权限验证。
- 普通后台或应用凭据不自动取得组织权限；未声明明确系统动作边界的后台任务不能访问组织资源。
- 已有无组织记录不自动推断或回填归属，启用组织策略后不能降级移除边界。

## 关联 Issue

无。

## 兼容要求

- node: Node.js 24 or newer for maintained toolchain
- generation: OpenXiangda V2; V1 unchanged
- platform: 须部署同源 contracts 及组织授权 SQL/后端；组织来源角色限定 self，subtree 授权由合法应用管理员显式管理
