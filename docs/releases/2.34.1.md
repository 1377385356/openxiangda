# OpenXiangda 2.34.1：持久申请受理恢复预算

支持配置最长30分钟的自动受理恢复，并保留首次明确提交时间和原申请编号。

## 新增能力

- useDurableCommand 可用 acceptanceRecoveryMs 配置120秒至30分钟的受理恢复预算。

## 修复问题

- 刷新及恢复原申请不再重新计算受理重试预算；截止后保留查询和迟到结果恢复能力。

## 受影响用户

- 需要较长排队等待的活动报名、预约和抢票应用开发者。

## 升级步骤

- 升级 openxiangda 到2.34.1，在需要长时间恢复的业务明确配置 acceptanceRecoveryMs。
- 验证原键恢复、截止后查询、未知应答及目标环境的完整排队容量。

## 已知限制

- 默认受理恢复预算仍为120秒；配置值是客户端自动入队预算，不是服务端最终完成承诺。
- 旧意图没有首次时间时，只能从首次明确恢复计时，无法证明历史发起时间。
- 受理成功不等于报名成功；实际容量需使用独立用户在目标环境验证。

## 关联 Issue

无。

## 兼容要求

- node: >=24
- workspaceGenerations: v2
- platform: 沿用 data.managed-concurrency.durable@1.0.0；不改变平台事实和permit协议。
- v1: V1引擎及业务不变。
