# 兼容非 HTTPS 私有入口的浏览器幂等操作

修复私有 HTTP 入口缺少 crypto.randomUUID 时工作流节点配置、路由和其他浏览器操作无法生成幂等标识的问题，统一使用 Web Crypto getRandomValues 回退生成 UUID。

## 新增能力

无。

## 修复问题

- 工作流节点配置保存不再依赖安全上下文专属的 crypto.randomUUID，HTTP 预发入口可以正常提交并保留原操作 ID 重试。
- 统一修复浏览器端管理、工作流、资源批量、文件和草稿操作的 UUID 生成，避免同类私有 HTTP 部署故障。

## 受影响用户

- 通过 HTTP 私有地址访问 OpenXiangda 管理后台或应用内工作流管理页面的用户。
- 使用工作流节点配置、路由、委托、恢复、资源批量和文件草稿等浏览器幂等操作的应用。

## 升级步骤

- 平台管理后台和应用统一升级到 openxiangda 2.62.1 与配套 CLI 2.8.13，重新生成封存七包。
- 部署后用 HTTP 预发入口保存一个工作流节点描述，确认后台 configuration.revision/history 有一次写入。
- 继续保留原请求 ID 语义，若结果未知只重试相同请求，不新建幂等键。

## 已知限制

- 浏览器仍需要 Web Crypto getRandomValues；极旧浏览器完全没有 Web Crypto 时会明确报错，不回退到可预测的 Math.random。
- 包版本升级和平台部署不替代真实角色权限、CAS 冲突和业务配置验收。

无。
