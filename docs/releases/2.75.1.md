# 公开查询批量读取与排序优先级修复

提供保留原平台权限的有界批量公开查询，修复多字段排序被重排的问题，配套同步官方技能资料。

## 新增能力

- createAnonymousPublicClient.queryBatch固定应用、环境和声明路由，按key/policy/query精确匹配逐项记录、聚合或错误回执。
- 每批最多10项、500条请求上限、64KiB输入，配套平台最多3项并发；不新增普通匿名Data API、权限缓存或Nest CRUD代理。

## 修复问题

- 应用打包器和共享目标编译器均保留publicQueries.sort声明顺序；修改排序优先级会正确改变配置摘要。
- 聚合items正确表示为直接含维度/指标的对象，不再声明成record.data；保留原value-only计数与单查询API。
- 缺失、重复、错位、超量或形状错误的批量回执明确拒绝，单项403/404/429/503不会变成空表或零。

## 受影响用户

- 使用匿名公开目录、仪器卡片、首页统计或其他多个具名只读查询的OpenXiangda V2应用。

## 升级步骤

- 先部署支持POST anonymous-public/public/query-batch的正式平台版本，再升级官方SDK与CLI；旧平台404应报告并完成平台更新。
- 升级后重新编译并发布TEST应用，以新不可变策略采用正确排序；不修改历史Head，不下载全表在前端弥补错误的前N选择。
- 使用原bootstrap获取正式浏览器凭证；批次每项显式指定策略、查询与key，调用方逐项处理成功或错误，延续原固定过滤和字段白名单。
- 保持真实页面请求数、P95/LCP与多角色业务验收独立进行，批量HTTP成功不代表每项成功。

## 已知限制

- 批次由独立只读查询组成，不保证同一数据库快照；不支持写入、业务动作或通知。
- 本发行不代表任何客户站点已部署或页面性能已达标；普通列表服务端分页与应用接入另行验收。

无。

## 兼容要求

- node: Node.js 24 or newer for maintained toolchain
- generation: OpenXiangda V2; V1 unchanged
- platform: Requires anonymous-public/public/query-batch; each item reuses existing public policy and Native authorization
