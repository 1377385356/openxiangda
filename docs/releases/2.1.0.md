# OpenXiangda 平台托管应用镜像上传

应用 Nest 后端在本机构建为 OCI 镜像后，通过平台登录态分片上传。平台负责应用归属校验、镜像存储和运行时拉取，开发者无需取得平台维护者个人镜像仓库的推送权限。

## 新增能力

- 发现并优先使用平台 backendImageUpload 能力，导出 linux/amd64 OCI 镜像并上传有界分片。
- 上传前校验本地镜像大小和摘要，复用已完成的镜像回执，并恢复分片传输中断。

## 修复问题

- 启用平台上传后，应用部署不再依赖开发者对平台维护者镜像仓库的推送权限。
- Docker classic image store 不支持 OCI 导出时，返回明确的 builder 配置指引。

## 受影响用户

- 声明可选 Nest 后端并通过 CLI 或 MCP 部署的 OpenXiangda 2.0 应用开发者。
- 维护共享应用运行时及平台镜像存储的平台管理员。

## 升级步骤

- 平台管理员先按部署运行手册准备镜像存储与凭据，再部署匹配的后端和网关。
- 在 Node.js 24 环境安装统一入口：npm install -g openxiangda@2.1.0。
- 更新 V2 项目锁定的工具链并刷新项目资料，核对平台上传能力后运行项目的 openxiangda deploy。

## 已知限制

- 当前仅支持 linux/amd64 单平台 OCI 镜像；默认单镜像上限为 1Gi，由平台配置控制。
- 已声明但未启用的平台上传能力会阻止部署，避免回退到个人镜像仓库推送。
- 镜像保留与垃圾回收由平台运维单独管理；现有版本仍可能需要历史镜像进行部署或回滚。
- 托管镜像开始使用后，后端回滚必须保留 Registry、持久卷、凭据和网关读取路由。

## 关联 Issue

无。

## 兼容要求

- node: >=24
- workspaceGenerations: v1, v2
- v1Policy: V1 应用保持原代际、版本锁定与登录绑定。
- platformPolicy: 平台托管上传需要匹配的后端、Registry 和网关发布，并启用 backendImageUpload；旧平台继续使用既有构建合同。
- backendBuild: 可选 Nest 后端仍在开发者电脑上使用 Docker Buildx 构建，需要支持 OCI exporter 的 builder。
- releaseChannels: latest / stable-v2：V2 正式版；legacy-v1：V1 维护版；alpha：预发布。
