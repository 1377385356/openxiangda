# 审批命令与业务数据原子提交契约

固定 Workflow 命令处理器可将审批或撤回交给已声明的受控业务动作，并在原工作流令牌和同一事务中提交 Native 数据变更。

## 新增能力

- 工作流定义可声明 approve、reject、withdraw 的固定 Named Action 处理器；双编译器校验操作、主体与能力引用并要求 workflow.business-data-command@1.0.0。
- 浏览器 SDK 从原 Workflow Surface 和当前操作目录分发固定动作，保留原令牌、命令 CSRF、幂等键及未知结果恢复语义；Nest SDK 透传已验证动作证明。

## 修复问题

无。

## 受影响用户

- 需要审批、撤回与关联业务记录在同一事务完成的 OpenXiangda 2.0 应用。

## 升级步骤

- 安装同一发行组合的 contracts、Devkit、Nest、根包和 CLI，重新生成应用契约；在支持 workflow.business-data-command@1.0.0 的平台上启用固定处理器。
- 应用为每个固定操作实现受控 Named Action，显式提交主体修订、Native 守卫与操作以及预期工作流结果，并按真实角色测试拒绝和撤回。

## 已知限制

- 未声明处理器的工作流行为不变；固定处理器只支持 approve、reject 和 withdraw，其他会改变流程状态的逃逸操作在已绑定流程中受限。
- 能力依赖配套平台内核；仅有 SDK 或字段声明不能实现原子业务效果。现有流程实例不会自动迁移或补发效果。
- 本地候选的源码和契约测试不等于平台激活或应用业务验收。

## 关联 Issue

无。

## 兼容要求

- node: >=24
- platform: workflow.business-data-command@1.0.0；未实现该能力的服务器须拒绝绑定应用。
