# OpenXiangda 2.12.0：平台原生数据自动化

数据事件可直接触发平台 Native 数据动作，省去应用 HTTP 接收链路；发布计划固定捕获字段与目标资源，业务效果与执行结果原子提交。

## 新增能力

- events.subscriptions.execution 支持 native-data v1 声明式 create/update/delete，无需 Nest 应用后端。
- 共享编译器自动派生事件捕获字段及目标模型摘要，新增 events.native-data-actions 能力检查。

## 修复问题

- 保留旧 Webhook 消费者与处理器契约，运维查询区分 Native 执行计划。
- 包含已合并的后台入口状态修复与 PC 优先开发引导，菜单缺失、无权限及未知地址分别展示。

## 受影响用户

- 使用平台数据自动化和 OpenXiangda V2 事件订阅的应用。
- 平台维护者必须同步升级匹配的共享 Native 校验器；V1 业务引擎保持独立。

## 升级步骤

- 先部署支持 events.native-data-actions 1.0.0、同版共享 Native 校验器和 SQL 扩展迁移的平台后端。
- 将应用依赖升级到 openxiangda 2.12.0 并按普通测试发布、验收和生产晋级流程交付。
- 简单数据动作按 execution 显式启用，外部 Webhook 与自定义代码继续使用现有处理器。

## 已知限制

- 首版 Native 动作仅支持明确源资源的数据事件，最多 16 个操作、每个 32 字段及 64 KiB 输入，不执行脚本、SQL 或 HTTP。
- 不兼容的目标模型变化会停止旧动作并报告错误；回退平台前需停用并排空 Native 动作。
- 按需事件不能重放从未捕获的历史；权限过滤的轻量操作历史由配套平台提供。
- 发行包验证不能代替客户环境的实际部署及容量测试。

- v1: 独立 legacy-v1 引擎，不引入兼容桥
