# OpenXiangda 2.22.3：草稿状态保持表单专属

修复 Native 编译器对 draftState 的执行校验边界，使默认与具名详情布局和公开 JSON Schema 一致地拒绝草稿工作区状态。

## 新增能力

无。

## 修复问题

- 默认详情布局和具名视图详情布局不再接受 draftState；该声明继续只允许出现在默认表单和具名表单上。
- 公开 Surface 键清单新增表单与详情的独立白名单，服务端消费者不再需要把同一 layout 白名单错误地复用于两个不同 Surface。

## 受影响用户

- 使用 OpenXiangda 2.0 认证草稿工作区状态的应用开发者，以及复用 Native Surface 纯校验器或键清单的平台维护人员。

## 升级步骤

- 将应用对 openxiangda 的精确依赖升级到 2.22.3，按锁文件重新安装依赖，并执行 pnpm openxiangda skill install --force 刷新本地 Skill。
- 平台维护者应同步升级 openxiangda-contracts，并使用独立的 form/detail 键清单校验 Surface；已把 draftState 错误声明在 detail 下的配置需移回 form。

## 已知限制

- 本补丁只收紧编译期与服务端 Surface 校验边界，不会自行升级平台服务、执行数据库迁移或修改已部署应用。
- draftState 仍只保存受声明约束的临时工作区状态，不是业务 Data API 字段、工作流事实或永久文档存储。

## 关联 Issue

无。

## 兼容要求

- node: >=24
- workspaceGenerations: v2
- platform: 完整草稿工作区能力仍要求升级到支持认证草稿原子消费和 draftState Schema 的平台服务，并应用对应的 expand-only SQL migration。
- v1: V1 工作区与维护引擎不受影响。
