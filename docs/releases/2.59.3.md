# 开发者AI应用自助操作与主线工具组合

让AI沿用当前应用权限直接诊断事件、复用加密环境凭据、配置通知和恢复指定投递；发行同源主线已评审的流程及编译契约。

## 新增能力

- admin operations和MCP application_operations发现20项有界操作；admin execute及application_operation直接执行，必须明确环境，密钥仅返回元信息。
- 角色审批可按固定代码步骤或事实的选人结果取当前有效角色候选；平台必须提供workflow.role-input-selection能力，缺失时拒绝新声明。
- 流程表单支持已加载固定子表行及按原Native资源授权读取材料；流程图支持展开已声明代码逻辑说明。

## 修复问题

- 当前能力目录完整合法闭包不再受旧64项上限误拒绝；未知代码、重复项及制品绑定仍拒绝。
- 补正可编辑未参与流转事实投影的一层owned子表；固定子表条件隐藏采用当前表单值。
- 流程画布就绪后才开放导航，用户导航不再被迟到初始化覆盖；大型AppSpec支持512文件并保留原字节界限。

## 受影响用户

- 使用V2开发者CLI/MCP进行应用运维，或使用本批流程/编译增强的应用。稳定V1独立维护。

## 升级步骤

- 精确更新完整工具组合，刷新工作区Skill和AGENTS平台区块并重启MCP。先读docs application-operations及admin operations --json。
- 共享校验器须与平台安装的openxiangda-contracts 2.71.0配对；已有生产应用保持原不可变版本，升级工具不代表重新部署业务。

## 已知限制

- 沿用当前应用管理授权；首次账号授权、权限委托和外部身份目录维护仍由原owner处理。旧平台缺少接口时明确拒绝，不使用SQL或保护绕过。
- 通道健康成功不证明实际老师收件或已读。恢复只处理指定原投递，不自动导入、重建业务、批量重发历史通知或读取密钥明文。

- v1: V1不消费本批V2契约或运行时
