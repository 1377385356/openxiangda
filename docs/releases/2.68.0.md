# PC流程管理、条件人员编辑与开发反馈整合

统一交付按动作授权的PC流程管理、条件人员规则编辑、Connected Dev原运行诊断与编译器任务前提投影，并同步业务迁移和发布指导。平台能力需配套服务端及管理前端后按明确环境启用。

## 新增能力

- PC流程设计器按查看、编辑、发布和办理配置四种动作呈现已发布/草稿读面，失权或结果未知时保留输入和原操作查询。
- 条件人员规则支持有序条件与否则、完整assignment保留和发布上下文校验；新节点允许保存受限不完整草稿，正式发布仍严格。
- MCP契约上下文增加分页prerequisites选择器，直接投影sealed compiler的能力与任务声明，不代替目标或角色验收。

## 修复问题

- Connected Dev保留字段位置、原configurationRunId/causeCode与拒绝分类，避免对需要修配置、查原运行或TEST部署的问题一律建议重跑。
- 生产回退明确使用已发布配置和真实数据；补齐V1到V2业务迁移、PC流程授权及原结果恢复的单源资料。
- 条件规则排序按钮提供稳定可访问名称，同批更新CLI模板精确BOM。

## 受影响用户

- 维护V2应用和PC流程设计/办理配置的开发者与管理员。
- 使用CLI/MCP开展连接开发、声明检查和业务迁移的团队。

## 升级步骤

- 按工作区锁定版本安装完整根包组合并刷新同版本Skill；不自动迁移V1项目。
- 平台先消费正式contracts2.88.0、同批浏览器SDK与sealed管理前端，并完成服务端与实际角色验收，再为明确TEST环境UUID启用委托流程管理。
- 已有未知操作继续查询原operationId/run；生产只晋级已经验收的原TEST版本。

## 已知限制

- SDK发行不等于平台部署或业务验收，环境开关默认空；仅安装npm包不会启用角色管理授权。
- 流程设计和授权管理本批仅针对PC，不扩大移动管理画布范围。
- 条件抄送、嵌套条件、发起自选和应用provider不在本次条件编辑范围；旧平台缺少上下文或能力时保持关闭。
- 测试数据回收仍仅native-data-only，复杂域与历史数据不能自动清理；语义扫描仍observe-only，不授予强制激活许可。

- generation: OpenXiangda V2; no automatic V1 migration
- platform: Paired contracts2.88.0 backend and sealed admin SDK required for new workflow features
