# 原生数据事件接收契约修复

修复当前平台原生数据事件在 Nest 自动化接收端的 Schema 不匹配，保持签名验证和幂等回执边界。

## 新增能力

- 本次为事件契约修复，不新增业务能力。

## 修复问题

- 移除事件数据体已经退役的 capturePlanRevision 必填要求；捕获身份继续由平台不可变事件账本持有。
- 接收当前用户角色并集 user_union 操作人的签名事件，并同步类型与开发测试夹具。

## 受影响用户

- 使用当前原生 Data API 并通过 Nest 消费数据事件的 OpenXiangda 2.0 应用。

## 升级步骤

- 将 V2 应用的 openxiangda 精确依赖升级为 2.2.1，更新锁文件并通过标准测试部署后验证事件回执。

## 已知限制

- 升级不会自动重放历史失败事件；按原事件和应用幂等标识使用平台运维操作恢复。

## 关联 Issue

无。

## 兼容要求

- node: >=24
- workspaceGenerations: v1, v2
- v1Policy: V1 引擎与应用契约不变。
- platformPolicy: 适用于由不可变捕获计划驱动的当前 V2 原生事件；应用需重新部署接收端。
