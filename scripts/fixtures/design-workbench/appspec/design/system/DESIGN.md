# 事项办理工作台设计

状态：实现能力样例，尚未取得用户对这个具体画面的确认。范围是中立事项的查找、查看详情和填写办理记录；所有内容是示例，不是业务统计或真实审批。未连接远端数据；不定义平台客户模型。

## 1. Visual Theme & Atmosphere

方向为“清晰的日常办理台”。主任务是尽快辨认下一件需要处理的事并完成它。温暖纸色提供环境，白色任务区承载信息，深绿色标识主要动作。显著的中文宋体标题提供方向感，正文用可读的中文无衬线。工作台不放无任务依据的指标、营销插画或多组装饰卡片。

## 2. Color

所有颜色数值在 tokens.css。中性层区分页面、内容和辅助文字；主操作用 accent，已选事项使用浅底加边界和文本共同说明。待补充使用文字和温和警示色。错误有明确文案与恢复动作，不靠颜色表达。

## 3. Typography

中文主标题以宋体和较大留白建立单一入口；正文与控件使用 PingFang SC 或 Microsoft YaHei 回退。中文标题行高至少 1.3，不使用负字距。表单、详情和列表的标题层次一致；日期和小字不与任务名争抢注意力。字体无需外部下载。

## 4. Spacing & Grid

数值 token 只在 tokens.css。PC 是列表与详情两栏，首列承担识别和筛选，右栏承担办理信息；分隔和间距胜于卡片套卡片。较窄屏幕只保留当前任务面，使用明确返回动作；触摸控件有足够点击面积。

## 5. Layout & Composition

页面上部为当前工作台标题和范围说明；主区先给任务筛选与列表，再给选中事项详情。PC 用户不必离开列表即可查看资料；手机用户点入详情后返回列表。新建从单一主要动作进入表单。列表支持搜索，空结果可清除条件；没有数据时不给虚构统计。长标题换行，不水平挤出视口。

## 6. Components

通用 PC 控件使用 AntD，业务输入复用享搭 ResourceFormContent/Field Kit（必填、文本、日期、选项）；移动表单复用同一字段定义的 Mobile 控件。Provider 读取派生主题，弹层仍在同一作用域。样例本地记录状态只为原型交互，真实实现需由平台 Data API 提供，不沿用本地数组或模拟授权作为业务真相。

## 7. Motion & Interaction

有意义的反馈包括选中态、按钮提交中、表单校验、提交结果和关闭前保留编辑的选项。原型提交延迟有界；失败保留输入，恢复后用户可重试。遵循 reduced-motion。主题对照切换必须保持正在填写的字段值，不能 remount 表单。

## 8. Voice & Brand

标题、按钮和错误使用具体任务语言：“办理事项”“填写记录”“暂无匹配事项”。“样例”标记持续可见，状态演练放在独立折叠工具区。没有企业品牌输入，本视觉是明确的推断，不冒充用户已有品牌。

## 9. Anti-patterns

不重复侧栏、不复制平台权限、不编造 KPI、不清空失败输入、不把无权读显示为空列表。不强制上游的单屏手机框、两处 accent 数量或字体禁令；以可辨认任务、中文阅读和可访问性解释选择。

## Evidence and contract

用户提供：整体设计可以借 OpenDesign 改善，已有 PC/移动组件可复用并优化。观察：Provider 缺少视觉输入；上游 reference-design-contract/frontend-design/polish 提供真实方法。推断：选择中立事项工作台作为结构与控件适配实验，采用温暖中性底和主从布局。参考只使用方法，不复制任何产品画面、标识或客户内容。

Keep：字段值、必填校验、PC/移动语义、当前平台能力边界。Change：整体构图、层次、色彩、表单和弹层视觉。Do not copy：原型中的本地状态、模拟拒绝和演练按钮到生产业务。

## Implementation handoff

读取本文件、manifest.json 和 tokens.css；Vite 样例从同一 CSS 源派生 AntD theme，移动映射使用可继承的 --oxa-mobile-* CSS 变量。实现主体 main.tsx 与 layout.css。首个产物证明列表→详情→表单→提交、错误保留输入、移动返回和主题变化不丢字段。浏览器检验之后把真实发现记入 verification.md；先保持此状态为 prototype，不写假确认。
